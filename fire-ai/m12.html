12 Claude Code로 내 화면

모듈 12 (심화 3). Claude Code로 내 PRD 화면 만들고 배포하기

📌 이 과정의 Claude Team 계정에는 Claude Code가 포함되어 있어 모두 직접 실습합니다.

모듈 10에서는 강의평가 화면을 손으로 올리고(커밋) 배포했습니다. 이번에는 모듈 05에서 쓴 내 업무 PRD를 AI 에이전트(Claude Code) 에게 건네 내 화면을 만들게 합니다. 말로 지시하면 Claude가 저장소에 파일을 만들고, 시험하고, 커밋·푸시까지 합니다. 사람은 검토하고 승인한 뒤 배포합니다.

과정의 마지막 장면은 각자 자기 업무 화면을 휴대폰으로 여는 것입니다.

모듈 08의 AI 브라우저(Aside)가 웹사이트 화면을 조작했다면, Claude Code는 저장소의 파일과 코드를 조작합니다.

이 모듈의 핵심은 "AI가 해 준다"가 아니라 "AI가 한 일을 내가 검토하고 승인한다" 입니다.

 모듈 10 (손으로):  나 ── 복사·붙여넣기 ──▶ GitHub ──▶ Vercel
 모듈 12 (AI와):    나 ── 지시 ──▶ Claude Code ── 커밋·푸시 ──▶ GitHub ──▶ Vercel
                     ▲                                          │
                     └──────────── 변경 내용 검토·승인 ◀──────────┘

💡 모듈 6에서 만든 스킬은 Claude Code에서도 같은 방식으로 씁니다. 업무 방법을 SKILL.md로 적어 두면, 사람에게 하듯 AI 에이전트에게도 매뉴얼을 건넬 수 있습니다.

이 과정의 진행 (Claude Team)

누가 하는 일
교육생 모두 각자 새 저장소 my-tool 에서 0~6단계. 화면 주제는 A. 내 PRD 또는 B. 공공데이터 중 하나
강사 앞 화면에서 한 단계 먼저 보여 주고, 4단계(검토)는 함께 읽기

0단계: 준비 (10분)

① 새 저장소 만들기 (모듈 10의 2단계와 같은 방법)

  1. GitHub 오른쪽 위 [+] → [New repository]
  2. Repository name: my-tool
  3. Private 선택 — 내 업무 내용이 담기므로 이번에는 비공개
  4. Add a README file ✅ 체크 (빈 저장소면 Claude Code가 작업을 시작하지 못합니다)
  5. [Create repository]

② Claude Code 연결

  1. 업무 Chrome 프로필에서 claude.ai/code 접속 (Claude Code 웹 버전. 프로그램 설치가 필요 없어 행정망 PC에 적합)
  2. GitHub 연결: 안내에 따라 Claude GitHub 앱을 설치
    • 저장소 선택에서 Only select repositories → my-tool 하나만 선택
  3. 작업할 저장소로 my-tool 선택

1단계: 내 PRD 다듬기 (5분)

옵시디언 01_기획(PRD) 의 내 PRD를 열어 세 가지만 확인합니다.

확인 이유
4번 핵심 기능이 3~5개인가? 한 시간 안에 만들 수 있는 크기. 많으면 "있으면 좋음"은 다음으로
6번 범위 밖에 "로그인, 여러 사람 공유(데이터베이스)" 가 있나? 기록은 이 브라우저에만 저장하는 화면으로 만든다 (10에서 확인한 한계 그대로)
실제 이름·연락처·내부 자료가 들어 있지 않나? 저장소와 AI에게 건네는 내용이므로 예시로 바꾼다

1단계-B: 공공데이터 파일 준비 (B를 고른 경우, 5분)

아래 세 파일 중 하나를 고릅니다. 처음이면 기본을 권합니다.

구분 파일 (공공데이터포털에서 이 이름으로 검색) 크기 만들어 볼 화면
기본 소방청_화재인명피해 지역별 성별 현황 작은 표 시도별 사상자 막대그래프, 전국 평균보다 많은 지역 강조
대안 소방청_가스누출(폭발) 화재 발생 현황 약 300줄 연도·장소별 건수, 많은 장소 순위
도전 소방청_연간화재통계 약 3만 7천 줄 (화재 1건 = 1줄) 시도·장소·발화요인별 집계, 많은 순 강조. 파일이 커서 시간이 더 걸림
  1. data.go.kr (공공데이터포털)에서 위 파일 이름으로 검색 → 파일데이터 → [다운로드] (로그인 없이 받을 수 있음)
  2. 받은 파일 이름을 data.csv 로 바꾸기 (한글·띄어쓰기가 든 파일 이름은 웹 주소에서 말썽이 날 수 있음)
  3. GitHub my-tool 저장소 → [Add file] → [Upload files] → data.csv 끌어다 놓기 → [Commit changes]

공공데이터는 누구나 쓸 수 있게 공개된 자료라 비공개 저장소에 올려도, 배포해서 보여 줘도 됩니다. 다만 화면에 출처(공공데이터포털, 제공기관, 기준일) 를 꼭 적습니다.

2단계: Claude Code에 지시하기 (5분)

A. 내 PRD 화면

이 저장소에 아래 PRD의 업무 화면을 만들어 줘.

(여기에 내 PRD 전체를 붙여넣기)

- index.html 파일 하나로 만들고, 외부 서버나 데이터베이스 없이 기록은 이 브라우저(localStorage)에만 저장해 줘
- 휴대폰 화면(폭 약 400px)에서 가로 스크롤 없이 보이게 해 줘
- 실제 개인정보 대신 예시 데이터로 처음 화면을 보여 줘
- 다 만든 뒤 PRD 7번 성공 기준대로 시험해 보고, 기준마다 통과 여부를 표로 알려 줘
- 커밋 메시지는 한국어로 "내 PRD 화면 v0.1"

B. 공공데이터 화면

이 저장소의 data.csv는 공공데이터포털에서 받은 "[파일 이름]" 자료야.
이 데이터로 한눈에 보는 현황 화면을 index.html 파일 하나로 만들어 줘.

- 먼저 CSV의 칸 이름과 줄 수를 확인해 알려 주고, 어울리는 표·그래프 3가지를 제안한 뒤 첫 번째로 만들어 줘
- CSV가 EUC-KR(CP949)일 수 있으니 한글이 깨지지 않게 읽어 줘
- 외부 서버나 외부 프로그램(라이브러리) 없이 같은 저장소의 data.csv를 읽고, 그래프도 직접 그려 줘
- 휴대폰 화면(폭 약 400px)에서 가로 스크롤 없이 보이게 해 줘
- 화면 아래에 출처(공공데이터포털, 제공기관, 기준일)를 적어 줘
- 다 만든 뒤 화면의 숫자 3개를 CSV 원본과 대조해 맞는지 표로 알려 줘
- 커밋 메시지는 한국어로 "공공데이터 화면 v0.1"

3단계: Claude가 일하는 모습 지켜보기 (10분)

화면에 Claude가 하는 일이 차례로 나타납니다.

보이는 것 뜻
파일 만들기 (초록 줄) 새로 쓴 코드
시험 실행 만든 화면이 PRD 성공 기준대로 동작하는지 확인
커밋·푸시 변경 내용을 기록해 GitHub로 올림
  • 중간에 허락을 묻는 화면이 나오면 무엇을 하려는지 읽고 승인합니다. 모르는 내용이면 승인하지 말고 손을 들어 주세요.
  • Claude Code는 보통 main(운영)이 아니라 별도 작업 줄기(브랜치) 에 올립니다. 원본을 바로 건드리지 않는 안전장치입니다.

4단계: AI가 한 일 검토하기 (5분) ⭐

  1. Claude가 보여 준 표를 확인합니다. A는 성공 기준 표를 내 PRD 7번과 대조, B는 숫자 대조 표를 보고 하나는 직접 CSV(엑셀)를 열어 맞는지 확인. 안 맞으면 "○○가 안 맞아, 고쳐 줘"로 이어서 지시
  2. GitHub 저장소 → 위쪽 브랜치 선택(main 이라고 적힌 버튼) → Claude가 만든 브랜치 → 커밋 기록(시계 아이콘) → Claude의 커밋
  3. 확인할 것:
    • PRD에 적은 기능이 들어 있나? 범위 밖으로 정한 것을 멋대로 넣지 않았나?
    • 내 실제 정보나 모르는 외부 주소가 들어가지 않았나?

5단계: 합치고 배포하기 (10분)

  1. GitHub에서 Compare & pull request (또는 Claude Code 화면의 PR 만들기) → 변경 내용 확인 → Merge pull request → Confirm merge
  2. Vercel 대시보드 [Add New…] → [Project] → my-tool → [Import] → [Deploy] (모듈 10의 5단계와 같음)
    • 목록에 my-tool 이 안 보이면 Adjust GitHub App Permissions 에서 my-tool 접근을 추가
  3. Domains 주소를 QR로 만들어 내 휴대폰으로 열기 (모듈 10의 QR 방법)
 내 PRD ──▶ Claude Code ──▶ 브랜치 ──(검토)──▶ 합치기(Merge) ──▶ main ──▶ Vercel ──▶ 📱 내 화면

6단계: 한 번 더 고치기 — 미리보기로 확인 (선택, 10분)

이제 저장소가 Vercel에 연결되어 있으니, 고칠 때마다 미리보기(Preview) 주소가 따로 생깁니다.

  1. Claude Code에 수정 하나를 지시: 예) "제목 아래에 사용 방법을 한 줄로 넣어 줘", "버튼 색을 소방 적색으로"
  2. Vercel Deployments → Claude 브랜치의 배포 → Visit 으로 미리보기 확인
  3. 운영 주소(Domains)는 아직 그대로인지 확인 → 괜찮으면 합치기 → 운영 주소에 반영
주소 무엇을 보여 주나
미리보기 (Preview) 아직 합치기 전, Claude 브랜치의 결과
운영 (Production, Domains) main 의 결과. 실제로 쓰는 주소

자주 막히는 곳

상황 해결
claude.ai/code 에 들어가지지 않음 Team 화면이 맞는지 확인(왼쪽 아래 Team 이름). 맞으면 관리자 설정에서 Claude Code 허용 여부 확인. 행정망 차단이면 전산 담당자 문의
저장소 목록에 my-tool 이 없음 GitHub 앱 설정에서 해당 저장소 접근 허용 추가
Claude가 시작하지 못하고 저장소가 비었다고 함 저장소를 만들 때 Add a README file 을 체크하지 않은 것. GitHub에서 README를 하나 만들고 다시
Claude가 여러 파일을 만듦 지시문에 "index.html 하나로" 조건이 있는지 확인. 원치 않으면 합치지 않고 지시를 다시
화면이 PRD와 다름 PRD 7번 성공 기준을 구체적으로 고친 뒤 "이 기준대로 다시 맞춰 줘"
(B) 한글이 깨져 보임 "data.csv가 EUC-KR이야. 한글이 깨지지 않게 다시 읽어 줘"
(B) 배포한 화면에 데이터가 안 나옴 data.csv 가 저장소 맨 위(index.html과 같은 곳)에 있는지, 파일 이름 대소문자가 같은지 확인
미리보기 주소가 안 보임 Vercel Deployments 에서 Claude 브랜치 배포가 Ready 인지 확인
잘못 합쳤음 Vercel Instant Rollback 으로 이전 배포로 즉시 되돌리고, GitHub에서 되돌리기(Revert)
