✋ 실습 약 15분 · 직접 해 보는 부분

① 저장소 만들고 Claude Code 연결하기 (7교시, 15분)

GitHub은 파일과 고친 기록을 보관하는 창고입니다(가입은 사전 과제). 고칠 때마다 남기는 기록(커밋)은 게임의 세이브 포인트라서, 화면이 망가져도 그 시점으로 돌아갈 수 있습니다. 오늘은 Claude Code가 이 창고에 코드를 쓰고, Netlify가 창고를 지켜보다가 바뀌면 저절로 다시 배포합니다.

저장소 만들기

  1. github.com 로그인 → 오른쪽 위 [+] → [New repository]
  2. Repository name: my-tool
  3. Private 선택
  4. Add a README file ✅ 체크 (빈 저장소면 Claude Code가 작업을 시작하지 못합니다)
  5. [Create repository]

Claude Code 연결

  1. 업무 Chrome 프로필에서 claude.ai/code 접속 (웹 버전이라 설치가 필요 없습니다)
  2. GitHub 연결 (PC에 프로그램을 까는 것이 아니라, 브라우저에서 Claude에게 내 GitHub 출입 권한을 주는 과정입니다)
    • 화면의 [GitHub 연결](Connect GitHub) 버튼 → GitHub 로그인(사전 과제에서 만든 계정)
    • Install Claude 권한 화면이 나오면 Only select repositories → my-tool 하나만 고르고 → [Install] (영어 버튼 이름이 Install이라 "설치"라고 부릅니다)
    • 다시 claude.ai/code 화면으로 돌아옵니다
  3. 작업할 저장소로 my-tool 을 고릅니다. 목록에 보이면 준비 완료입니다.

💡 왜 저장소 하나만 열어 줄까? 로그인은 "누구인지 확인"하는 사원증, 저장소 선택은 "어느 방에 들어갈 수 있는지" 정하는 출입 권한입니다. AI에게도 필요한 방 하나만 열어 줍니다.

💡 어제 06에서 PRD 인터뷰 스킬을 등록하지 못했어도 괜찮습니다. 이 프롬프트에 인터뷰 방법(한 번에 질문 1~2개, 7개 항목 순서, [확인 필요] 표시)이 모두 들어 있어서 스킬 없이도 똑같이 인터뷰가 진행됩니다. 스킬은 과정 뒤에 "○○를 기획하고 싶어" 한마디로 인터뷰를 시작하고 싶을 때 등록하면 됩니다: PRD 인터뷰 스킬 (ZIP) 내려받기 📎 PRD 인터뷰 스킬 (Claude에 바로 올리는 ZIP) 내려받기 → Claude 설정 → 기능(Capabilities) → 스킬(Skills) → [스킬 업로드] → 켜기 (06의 6-2와 같은 방법)

③ PRD 건네고 계획 먼저 받기 (7교시 끝, 5분)

GitHub 연결은 Claude Code에게 저장소 출입 권한을 준 것일 뿐, 내 PC(옵시디언)에 있는 PRD는 아직 Claude가 볼 수 없습니다. 그래서 PRD를 Claude Code 입력창에 붙여넣고, Claude가 직접 저장소에 PRD.md 파일로 저장하게 합니다. GitHub 화면에서 파일을 올릴 필요가 없습니다.

PRD가 저장소에 파일로 남으면 Claude Code가 언제든 다시 읽을 수 있고, 고친 기록(⑨의 변경 기록)도 쌓입니다. 설계도를 공사 현장 사무실 벽에 붙여 두는 것과 같습니다.

그리고 바로 만들라고 하지 않고 계획부터 받습니다. 공사 전에 시공 계획서를 받아 보는 것과 같습니다. 계획 단계에서 잘못을 찾으면 1분이면 고치지만, 다 만든 뒤에 찾으면 10분이 걸립니다.

  1. claude.ai/code 에서 저장소 my-tool 을 고릅니다.
  2. 옵시디언에서 PRD.md 를 열어 전체 복사합니다 (Ctrl + A → Ctrl + C).
  3. 아래 [바로 해 보기]의 칸에 붙여넣고 [프롬프트 복사] → Claude Code 입력창에 붙여넣어 보냅니다.

Claude가 PRD를 저장하고 계획을 쓰는 동안(1~3분) 쉬는 시간입니다.

읽을거리: 깃허브에는 무엇을 올릴까? (쉬는 시간에)

방금 PRD.md 가 저장소에 올라갔습니다. 그렇다고 내 일과 관련된 파일을 전부 올리지는 않습니다. 깃허브에는 다시 만들 수 없는 것과 사람이 직접 쓴 것을 올리고, 프로그램이 자동으로 만들어 내는 것이나 남이 보면 안 되는 것은 뺍니다.

보통 올리는 것

  • 코드 파일: 이제 만들 index.html 같은 것
  • 문서: PRD.md, README.md, 사용 설명서
  • 설정 파일: 어떤 라이브러리를 쓰는지 적은 목록 같은 것
  • 직접 만든 이미지·아이콘: 화면에 들어가는 그림
  • 테스트 코드: 프로그램이 제대로 도는지 확인하는 코드

보통 올리지 않는 것

종류 예 이유
자동으로 생기는 결과물 빌드 결과 폴더, 임시 파일 코드만 있으면 언제든 다시 만들 수 있음
내려받은 외부 라이브러리 node_modules 폴더 아주 크고, 목록만 있으면 다시 내려받을 수 있음
비밀 정보 비밀번호, API 키, .env 파일 한 번 올라가면 지워도 기록(커밋)에 남아 위험함
개인정보·실제 사용 기록 고객·민원인 정보, 사용자가 입력한 데이터 코드와 데이터는 따로 보관함
내 컴퓨터 전용 설정 편집기 설정, .DS_Store 다른 사람에게는 필요 없음
아주 큰 파일 동영상, 큰 데이터 파일 저장소가 무거워짐 (따로 보관하는 방법이 있음)

빼야 할 파일은 보통 .gitignore 라는 파일에 이름을 적어 둡니다. 그러면 실수로 커밋하는 일을 막을 수 있습니다. 회사 문서로 치면 "외부 반출 금지 목록" 입니다.

구분 파일
올리는 것 PRD.md(방금 올림), 만들 index.html, ⑩의 README.md
올라가지 않는 것 화면에서 내가 입력한 기록. 사용자 데이터라서 내 휴대폰 브라우저(localStorage)에 남는 것이 맞습니다
판단이 필요한 것 참고 자료(후기 원문, 사진, 메모). 올려도 되고 안 올려도 됩니다. 실제 개발이라면 docs/ 폴더에 함께 두는 경우가 많습니다. 단, 실명·연락처가 있으면 올리지 않습니다

⑥ AI가 한 일 검토하기 (8교시, 10분) ⭐

결재하기 전에 기안문을 훑어보는 것과 같습니다. 코드는 읽지 않습니다. 아래 네 가지만 확인합니다.

확인할 것 왜
1 시키지 않은 기능을 넣었나? 좋아 보여도 PRD에 없는 기능은 고장과 혼란의 원인
2 다른 사이트로 연결되는 것이 있나? 내 화면을 연 사람의 정보가 밖으로 나갈 수 있음

⑦ 합치고 배포하기 (8교시, 15분)

두 가지를 합니다. (가) 합치기로 연습장(브랜치)의 화면을 원본(main)에 넣고, (나) Netlify 연결로 원본을 웹 주소로 공개합니다. Netlify 연결은 처음 한 번만 하면, 그다음부터는 합칠 때마다 저절로 다시 배포됩니다.

 Claude Code ──[Create PR] 결재 올리기──▶ GitHub: 결재 요청서(PR) ──[Merge] 결재──▶ main ──(저절로)──▶ Netlify ──▶ 🌐 내 주소
                               (가) 합치기 = 결재                              (나) 처음 한 번 연결

(가) 합치기 = 결재 (5분)

PR(풀 리퀘스트)은 "연습장의 내용을 원본에 합쳐도 될까요?"라는 결재 요청서입니다. 영어 버튼 두 개만 기억하면 됩니다.

버튼 어디에 뜻
[Create PR] Claude Code 채팅 옆 패널의 Changes(변경 사항) 카드 결재 요청서를 올리기 (상신)
[Merge pull request] GitHub 화면 결재하기 (원본에 합치기)
  1. 결재 올리기: Claude Code 화면에서 채팅 옆 패널에 있는 Changes(변경 사항) 카드를 찾습니다. +120 -0 처럼 바뀐 줄 수가 적힌 카드입니다. 그 카드의 [Create PR] 을 누르면 결재 요청서(PR)가 제목·설명까지 채워져 바로 만들어집니다.
    • 채팅 옆 패널이 안 보이면: 화면 맨 위 세션 제목 줄의 패널 보기 아이콘(Show session rail) 또는 ⋮ 메뉴에서 켭니다.
    • 그래도 못 찾겠으면: 채팅창에 결재 요청서(PR)를 만들어 주고 주소를 알려 줘 라고 보내도 됩니다.
  2. Changes 카드에 생긴 결재 요청서(PR) 제목이나, Claude가 알려 준 주소를 누르면 GitHub 화면이 열립니다.
  3. 아래로 내려 초록 버튼 [Merge pull request] → [Confirm merge]
  4. 보라색 Merged 표시가 보이면 끝입니다. 옆의 [Delete branch] 는 눌러도 되고 안 눌러도 됩니다(다 쓴 연습장 지우기).

(나) Netlify에 연결하기 (처음 한 번, 10분)

  1. app.netlify.com → [Sign up] → GitHub 로 가입합니다. (이미 GitHub에 로그인돼 있어 가장 빠릅니다)
    • 가입 질문(무엇에 쓸지, 팀 이름 등)이 나오면 아무거나 고르거나 Skip 합니다. 요금제를 물으면 Free(무료). 카드는 넣지 않습니다.
  2. [Add new project](또는 Add new site) → [Import an existing project] → GitHub
  3. GitHub에서 Netlify에게 출입 권한을 주는 화면(Install Netlify)이 나옵니다 → Only select repositories → my-tool 하나만 선택 → [Install]. 이것도 PC에 까는 것이 아닙니다.
  4. 목록에서 my-tool 을 고르고, 설정은 아무것도 바꾸지 않은 채 맨 아래 [Deploy my-tool](또는 Deploy) 를 누릅니다.
  5. 1분쯤 지나 초록색 Published 가 보이면, 위쪽의 ○○○.netlify.app 주소를 눌러 PC에서 내 화면이 열리는지 봅니다.
  6. 주소 이름 바꾸기: Project configuration(또는 Site configuration) → Change project name → 예) run-log-hong → https://run-log-hong.netlify.app (이미 있는 이름이면 뒤에 숫자를 붙입니다)

⚠️ 배포한 주소는 누구나 열 수 있습니다. 저장소가 비공개여도 마찬가지입니다. 화면에 실제 이름·연락처·내부 자료가 없는지 한 번 더 봅니다.

⚠️ Netlify 연결이 막히면: GitHub my-tool 저장소에서 index.html 을 눌러 [Download raw file](⬇ 아이콘)로 내려받아 my-tool 폴더에 넣고, Netlify에 로그인한 상태에서 app.netlify.com/drop 에 폴더째 끌어다 놓습니다. 로그인하지 않고 올리면 1시간 뒤 사라집니다. 이 방법은 ⑨부터 고칠 때마다 다시 끌어다 놓아야 합니다.

단계 순서대로 정리했습니다. 막히면 먼저 옆 사람에게, 그다음 손을 들어 주세요.

단계 상황 해결
① claude.ai/code 에서 "Claude Code isn't available" 왼쪽 아래가 Team 계정인지 확인. 개인 계정이면 Switch organization 으로 Team으로 바꿉니다
① "GitHub access is required…"만 보이고 연결 버튼이 없음 강사(관리자)가 조직 설정 → Connectors 에서 GitHub 연결을 켜야 합니다. 손을 들어 주세요
① 처음 들어갔더니 Create your first cloud environment 화면 이름과 설정을 그대로 두고 [Create & finish]
① GitHub 로그인 때 인증 코드를 물음 새 PC라서 그렇습니다. 휴대폰 메일 앱에서 GitHub가 보낸 코드를 확인해 입력
① 저장소 목록에 my-tool 이 없음 Claude에게 출입 권한을 안 준 것입니다. github.com/settings/installations → Claude 옆 [Configure] → Repository access 에 my-tool 추가 → [Save]
① Claude가 저장소가 비었다고 함 저장소를 만들 때 Add a README file 을 체크하지 않은 것. GitHub 저장소 화면의 [Add a README] 로 하나 만들고 다시
② 인터뷰가 끝나지 않음 "지금까지 답한 것으로 PRD 정리해 줘"
③ Claude가 PRD.md를 저장하지 않고 계획만 씀 "아까 붙여넣은 PRD를 PRD.md로 저장하고 커밋해 줘"
③ 붙여넣은 PRD가 잘림 두 번에 나눠 보내거나, GitHub my-tool → [Add file] → [Upload files] 로 PRD.md 를 직접 올린 뒤 "PRD.md를 읽고 계획을 알려 줘"
④ 계획 없이 바로 만들어 버림 괜찮습니다. ⑥에서 똑같이 검토합니다
⑤ 오래 멈춘 것 같음 5분은 기다립니다. 그래도 그대로면 "어디까지 했는지 알려 주고 계속해 줘"
⑤ 사용량 한도 안내가 뜸 여럿이 동시에 쓰면 생깁니다. 안내된 시간만큼 쉬었다가 "계속해 줘"
⑤ 여러 파일을 만들었음 결재하지 말고 "index.html 하나로 다시 만들어 줘"
⑥ 화면이 PRD와 다름 "PRD.md의 성공 기준 ○번을 '○○'로 고치고, 그에 맞게 화면도 고쳐 줘"
⑦ [Create PR] 이 안 보임 채팅 옆 패널을 켭니다(세션 제목 줄의 패널 아이콘 또는 ⋮). 그래도 없으면 "결재 요청서(PR)를 만들어 주고 주소를 알려 줘"
⑦ Netlify 목록에 my-tool 이 없음 Netlify에 출입 권한을 안 준 것입니다. 목록 아래 Configure the Netlify app on GitHub → my-tool 추가
⑦ 배포 주소를 열면 Page not found index.html 이 저장소 맨 위에 있지 않은 것. "index.html을 저장소 맨 위로 옮겨 줘" → 결재
⑦ 주소 이름이 이미 있다고 함 뒤에 숫자나 이니셜을 붙입니다. 예) run-log-hong2
⑦ Drop으로 올린 화면이 사라짐 로그인하지 않고 올리면 1시간 뒤 사라집니다. Netlify에 로그인한 뒤 다시 끌어다 놓기
⑧ QR 메뉴가 안 보임 주소를 휴대폰 브라우저에 직접 입력하거나, PC 메신저로 내게 보내 휴대폰에서 엽니다
⑧⑨ 결재했는데 운영 주소가 그대로 1~2분 뒤 휴대폰에서 새로고침. 그래도 그대로면 Netlify Deploys 에서 배포가 끝났는지(초록 Published) 확인
⑨ 미리보기 주소가 안 보임 결재 요청서 화면 아래 확인 목록이 끝날 때까지 1~2분. Netlify Deploys 에도 "Deploy Preview"로 보임
⑨ 고쳤더니 휴대폰 기록이 사라짐 "v0.1에서 저장한 기록이 사라졌어. 저장 이름을 바꾸지 말고 고쳐 줘"
⑨ 잘못 결재했음 급하면 Netlify Deploys → 이전 배포 → [Publish deploy] 로 즉시 되돌립니다. 그다음 GitHub의 그 결재 요청서 화면에서 [Revert] → 새로 생긴 요청서를 결재
부록 한글이 깨짐 "data.csv가 EUC-KR이야. 한글이 깨지지 않게 다시 읽어 줘"
부록 화면에 데이터가 안 나옴 data.csv 가 index.html 과 같은 곳(저장소 맨 위)에 있는지, 파일 이름이 정확히 data.csv 인지 확인

마무리 (10교시): 결과 공유와 다음 걸음

10교시는 아래 순서로 진행합니다.

순서 시간 할 일
1 2분 처음 질문, 다시
2 20분 결과 공유: 한 사람씩 한 줄 + 휴대폰 화면
3 10분 관심사에서 업무로, 다음 4주 계획
4 10분 과정 평가 (강사가 질문지로 묻습니다)
5 8분 끝나기 전에: 사용 기간과 저장

1. 처음 질문, 다시 (2분)

첫날 1교시에 물었던 세 문장입니다. 지금은 어떤가요?

① AI는 검색을 조금 편하게 해 주는 것이다
② 프로그램은 개발자만 만든다
③ 나는 컴퓨터를 잘 못해서 어렵다

2. 결과 공유 (20분)

⑩에서 준비한 한 줄로 시작하고, 휴대폰으로 내 화면을 보여 줍니다(1분씩).

"나는 (무엇) 을 만들어 (어디에) 쓴다. 업무에서는 (무엇) 에 같은 방법을 쓰겠다."
예) "나는 등산 기록 화면을 만들어 이번 달 산행 횟수를 본다. 업무에서는 내가 관리하는 교육 장비 점검표를 같은 방법으로 만들겠다."

3. 관심사에서 업무로 (10분)

오늘은 관심사로 했지만 순서는 업무에서도 똑같습니다.

오늘 해 본 것 업무에서는
관심사 PRD 인터뷰 (②) 업무 도구 기획서, 개선 제안서
PRD를 저장소에 파일로 남김 (③) 기획서를 한곳에 두고 고친 기록 남기기
계획 먼저 받기 (③④) 기안 전 방향 보고
AI가 한 일 검토 (⑥) 결재 전 검토
결재 올리기 · 결재 (⑦) 상신 · 결재
휴대폰으로 성공 기준 시험 (⑧) 시범 운영과 점검표
짝이 써 보고 고칠 점 (⑧⑨) 동료 의견 받아 개선
기록이 내 휴대폰에만 남음 (⑧) 회신 취합이 번거로운 이유, 공용 시스템(백엔드)이 필요한 때

이틀 동안 업무 자동화 사다리를 다섯 칸 올라왔습니다.

① 잘 시키기      6하원칙 프롬프트                         (03)
② 자료 맡기기    프로젝트 · MD 파일                       (03 · 05)
③ 방법 맡기기    스킬 = 업무 매뉴얼                       (06)
④ 클릭 맡기기    AI 브라우저 · 루틴                       (08)
⑤ 내 도구 만들기 PRD → Claude Code → 검토 → 배포         (07 · 12)  ← 오늘 여기까지
⑥ 저절로 돌아가게 여러 사람 자료 모으기(백엔드), 정해진 때 자동 실행  (다음 단계)

여는 이야기의 여행길 도우미는 ⑥에 한 발 더 간 모습입니다. 날씨·주차처럼 실시간 정보는 서버와 공공데이터 API로 가져옵니다.

다음 4주 계획: 한 번에 다 하지 않아도 됩니다. 일주일에 한 번, 30분이면 됩니다. Claude Code는 Team 사용 기간(11. 16.경까지)에만 쓸 수 있으므로, 내 도구 만들기를 첫 주에 합니다.

3주 ③ 방법 맡기기 내 업무 스킬을 실제 문서에 3번 쓰고, 고칠 점을 반영해 다시 올리기 □
4주 ④ 클릭 맡기기 매주 반복하는 웹 확인 작업 하나를 AI 브라우저 루틴으로 만들기 □

4. 과정 평가 (10분)

강사가 질문지로 묻고, 둘러앉아 답합니다. 좋았던 것, 어려웠던 것, 시간이 모자랐던 교시를 솔직하게 말해 주세요. 2차 교육을 고치는 데 그대로 씁니다.
