손 풀기 (모듈 2)

안녕! 나는 오늘 처음 생성형 AI를 써 보는 사람이야.
너는 무엇을 잘하고, 무엇을 조심해서 써야 하는지 초등학생도 알 수 있게 5줄로 알려줘.

되묻기 (모듈 3)

이 작업을 잘하기 위해 내가 빠뜨린 정보가 있으면, 답하기 전에 먼저 질문해 줘.

좋은 지시 예시: 강의평가 참여 요청 안내문 (모듈 3)

[역할] 너는 소방학교 교육운영 담당자야.
[목표] 신임소방관 교육생에게 보낼 강의평가 참여 요청 안내문을 써 줘.
[맥락] 제12기 교육생 40명, 3주 과정 18과목. 평가 기간 9월 28일~10월 2일 17시, 휴대폰으로 참여, 익명, 약 3분 소요.
[형식] 제목 1줄, 인사말 2줄, 핵심 안내 4개 항목(글머리표), 평가 일정은 표로.
[조건] 정중한 존댓말, A4 반 장 이내, 확인되지 않은 내용은 [확인 필요]로 표시.

첨삭 예시: 강의평가 결과 보고 메일 (모듈 3)

[역할] 너는 소방학교 교육운영팀 담당자야. 교육운영과장님께 보고 메일을 쓰는 상황이야.
[목표] 제12기 강의평가 결과를 보고하고, 개선 필요 과목의 교관 면담을 요청하는 메일을 써 줘.
[맥락] 신임소방관 제12기 18과목, 응답 38명/40명, 전체 평균 4.2점(5점 만점).
       평균 3.5 미만 2과목: 화재진압 전술(이교관 반) 3.3, 소방 관계법규(최교관) 3.1.
[형식] 메일 제목 1줄, 본문 3문단(결과 요약 / 개선 필요 과목 / 요청 사항), 개선 필요 과목은 표로.
[조건] 정중한 존댓말. 개선 원인이나 면담 일정처럼 내가 주지 않은 정보는 [확인 필요]로 표시해.

파일 요약 (모듈 3)

첨부한 문서를 읽고
1) 핵심 내용 3줄 요약
2) 실제로 해야 할 일(To-do) 목록
3) 문서에서 모호하거나 빠진 부분
을 표로 정리해 줘. 문서에 없는 내용은 지어내지 마.

자유의견 요약 (모듈 3)

첨부한 강의평가 자유의견을 과목별로 정리해 줘.
- 과목마다 "좋았던 점 / 바라는 점"을 1~2줄로 요약
- 여러 과목에 공통으로 나온 의견은 따로 모아 줘
- 원문에 없는 의견은 만들지 말고, 표로 정리해 줘

프로젝트 지침 (모듈 3)

너는 소방학교 교육운영 담당자를 돕는 보조자야.
- 항상 정중한 존댓말로 답한다.
- 프로젝트에 올린 파일 내용을 우선 근거로 삼고, 파일에 없는 내용은 [확인 필요]로 표시한다.
- 일정·인원·준비물은 표로 정리한다.
- 답 끝에 "다음에 할 일" 1~3개를 제안한다.

스킬 만들어 달라고 하기: 결과보고서 양식 (모듈 6)

과정이 끝날 때마다 쓰는 "강의평가 결과보고서"를 우리 양식으로 써 주는 스킬을 만들어 줘.
양식: 제목 / 1. 개요(과정·기간·응답률) / 2. 결과 요약(전체 평균) /
      3. 개선 필요 과목(평균 3.5 미만, 표) / 4. 주요 의견 / 5. 조치 계획(표)
- name은 eval-report, SKILL.md 하나로
- description에 "언제 쓰는지"를 꼭 넣어 줘
- 자료에 없는 숫자나 조치 일정은 [확인 필요]로 표시하게 해 줘

스킬 파일 예시: 스킬 예시 파일

⭐ eval-report 스킬이 있으면 결과보고서는 한 문장이면 됩니다: 제12기 강의평가 결과보고서 써 줘 (자유의견·결과표 파일 첨부)

PRD 인터뷰 (모듈 5, 스킬이 없을 때)

너는 경험 많은 기획자야. 나는 "[내가 만들고 싶은 것]"을 기획하려고 해.
PRD를 쓰기 위해 나를 인터뷰해 줘.
- 한 번에 질문 1~2개만 해.
- 배경·목표·사용자·핵심 기능·화면 흐름·범위 밖·성공 기준 순서로 물어봐.
- 내가 다 답하면 Markdown 형식의 PRD 한 장으로 정리해 줘.
- 내가 말하지 않은 내용은 [확인 필요]로 표시해.

PRD 검토 (모듈 7, Gemini Notebook)

이 PRD에서 "범위 밖"으로 정한 것과, 성공 기준을 표로 정리해 줘.
그리고 PRD 안에서 서로 모순되거나 빠진 부분이 있으면 알려 줘.

슬라이드 만들기 (모듈 7, Gemini Notebook 스튜디오)

교육운영과장님께 "제12기 강의평가 결과와 집계 도구 도입"을 보고하는 5장짜리 발표 자료로 만들어 줘.
1장: 지금의 문제(종이 설문, 반나절 집계), 2장: 자유의견에서 나온 주요 개선 요구,
3장: 집계 도구의 핵심 기능, 4장: 이번에 하지 않는 것, 5장: 성공 기준과 다음 단계.
소스에 없는 숫자는 쓰지 마.

인포그래픽 만들기 (모듈 7, Gemini Notebook 스튜디오)

강의평가 결과보고가 만들어지는 순서(휴대폰으로 평가 입력 → 과목·교관별 자동 집계
→ 평균 3.5 미만 "개선 필요" 표시 → 결과보고서 작성)를 4단계 흐름 그림으로 만들어 줘.
자유의견에서 가장 많이 나온 개선 요구 3개를 아래에 함께 넣어 줘.
소방 적색을 강조색으로, 글자는 크게.

결재 보고서 (모듈 7, ChatGPT)

첨부한 PRD를 바탕으로 상급자 결재용 1페이지 보고서를 써 줘.
형식: 제목 / 추진 배경 / 주요 내용 / 기대 효과 / 향후 일정(표).
PRD에 없는 숫자는 만들지 말고 [확인 필요]로 표시해.

발표 개요 (모듈 7, ChatGPT)

이 PRD로 10분 발표를 하려고 해. 슬라이드 7장 구성으로
장마다 제목, 핵심 문장 1개, 들어갈 그림 아이디어를 표로 정리해 줘.

프로토타입 (모듈 7, Claude)

첨부한 PRD를 읽고, 핵심 기능(필수)만 동작하는 프로토타입 웹 화면을 만들어 줘.
- HTML 파일 하나로, 설치 없이 브라우저에서 바로 열리게
- 휴대폰 화면에서도 보기 좋게
- "범위 밖" 기능은 넣지 마
- 처음 열었을 때 예시 데이터 3개를 보여 줘

코드 한 줄씩 설명받기 (모듈 8)

첨부한 3-js.html을 코딩을 처음 보는 사람에게 설명해 줘.
<script> 부분을 한 줄씩, 비유를 들어서 설명하고
PRD의 어느 규칙과 연결되는지도 표로 정리해 줘.

기능 추가 요청하기 (모듈 8)

첨부한 3-js.html의 결과표를 "평균이 낮은 과목부터" 보이게 고쳐 줘.
바꾼 줄에는 주석으로 표시해 줘.

Firebase 공용 장부로 바꾸기 (모듈 10)

첨부한 index.html은 강의평가를 브라우저(localStorage)에 저장하는 집계 화면이야.
첨부한 PRD v0.4에 맞게, 평가를 Firebase Firestore에 저장하도록 고쳐 줘.

- 내 Firebase 설정값은 아래와 같아:
  (여기에 firebaseConfig 붙여넣기)
- HTML 파일 하나로 유지하고, Firebase는 공식 CDN(gstatic.com)의 모듈 방식으로 불러와 줘
- 컬렉션 이름은 evaluations, 필드는 subject, instructor, score(1~5 정수), date(YYYY-MM-DD)만 써 줘
- 문서 ID는 Firestore가 자동으로 만들게 해 줘 (addDoc)
- 모든 평가를 실시간으로 받아서 과목·교관별 집계는 화면에서 해 줘
- 마지막 응답 취소, 전체 초기화, 예시 데이터는 없애 줘
- 나머지 화면 디자인과 개선 필요 판정(평균 3.5 미만)은 그대로 둬

브라우저 에이전트에게 한 번 시키기 (모듈 12, Aside)

https://(내 강의평가 주소).vercel.app 을 열고
과목 "시연과목", 교관 "시연교관"으로 만족도 5, 3, 2 평가를 차례로 제출해 줘.
그다음 결과표에서 "개선 필요"로 표시된 과목과 교관, 평균을 모두 알려 주고,
결과 내려받기 버튼을 눌러 파일을 저장한 뒤 파일 이름을 알려 줘.

루틴으로 만들기 (모듈 12, Aside)

평가 기간(9월 28일~10월 2일) 동안 매일 오후 4시에 강의평가 주소를 열어서
전체 응답 수와 "개선 필요" 과목·교관 목록을 확인하고, 결과를 세 줄로 정리해 줘.

Claude Code에 기능 추가 맡기기 (모듈 11)
