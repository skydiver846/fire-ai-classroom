모듈 09 (심화 1). HTML · CSS · JavaScript로 준비물 화면 뜯어보기

모듈 7에서 Claude가 여행 준비물 체크 화면을 만들어 줬고, 모듈 8에서는 AI 브라우저가 그 화면을 대신 조작했습니다. 하지만 맞는 도구가 없으면 직접 만들어야 합니다. 배포하기 전에, 그 화면이 어떤 재료로 어떤 순서로 만들어지는지 열어 봅니다. 코드를 외우는 시간이 아닙니다. 열어 보고, 한 군데 바꿔 보고, 바뀐 결과를 눈으로 확인하는 시간입니다.

⏱ 수업에서는 20분 맛보기입니다 (2일차 7교시 앞부분, 바로 이어서 10 Netlify 배포).

순서 시간 할 일
준비 1분 이 페이지를 엽니다 (파일 내려받기 없음)
1단계 HTML 3분 단계마다 있는 [바로 해 보기] 화면에서 [추가] 와 체크 눌러 보기 → 표가 안 바뀜 (빨리 끝난 분은 ✏️ 제목 바꾸기)
2단계 CSS 3분 1단계와 번갈아 보기 → 같은 내용에 옷만 입힘 → ✏️ 버튼 색 한 줄 바꾸기(모두 함께)
3단계 JavaScript 6분 준비물 추가·체크 → ✏️ 코드에서 rate < 50 을 30으로(같은 33%가 "순조로움"으로) → [새로고침] 하면 사라짐
4단계 완성본 4분 무엇이 더해졌는지 보기 → [새로고침] 해도 남음 → 이 파일을 10에서 공개

실습 상자 아래의 ✏️ 코드 직접 고쳐 보기는 실제 파일 코드를 페이지 안에서 고치고 [▶ 실행] 하는 칸입니다(메모장·저장·F5 없이). 수업에서는 표에 적은 한 가지씩만 하고, 나머지 도전 과제는 과정 뒤에 합니다. 각 단계의 코드 읽기 표·AI로 바꿔 보기·개발자 도구·더 알아보기·응용 실습도 과정 뒤 복습용입니다.

준비 (1분)

수업에서는 파일을 내려받지 않습니다. 단계마다 이 페이지 안에 있는 [바로 해 보기] 화면에서 실제 실습 파일을 그대로 눌러 보고, 아래 ✏️ 코드 직접 고쳐 보기에서 코드를 고쳐 [▶ 실행] 합니다. 화면이 작으면 [새 창으로 열기] 를 누릅니다.

(과정 뒤) 실습 파일 4개: 메모장으로 직접 고치거나 AI에게 첨부해 바꿔 볼 때는 강의 사이트 [실습 파일 내려받기] 에서 4개를 받습니다.

파일 단계 저장소 위치

2-css.html + 옷 prototype-demo/steps/2-css.html

index.html 완성본 (모듈 7 결과와 같은 기능) prototype-demo/index.html

  • 보기: 파일을 더블클릭하면 Chrome에서 화면이 열립니다.
  • 코드 읽기: 파일 오른쪽 클릭 → 연결 프로그램 → 메모장. 읽기만 합니다.
  • 바꾸기: 이 모듈에서는 AI에게 바꿔 달라고 하고, 나는 화면과 바뀐 줄을 확인합니다. 단계마다 같은 방법입니다.

1단계: HTML = 뼈대 (4분)

아래 화면은 1-html.html 입니다. 색도 배치도 없이 글자만 나열되어 있습니다. 정상입니다.

과정 뒤에 더 해 보기 코드 읽기 (과정 뒤)

메모장으로 열어 보면 <이름>내용</이름> 모양이 반복됩니다. 이것을 태그라고 합니다.

태그 뜻 준비물 화면에서
<h1> 가장 큰 제목 우리 가족 여행 준비물 체크
<p> 문단 "경주 2박 3일 · 챙김률 50% 미만은 서둘러요"
<form> 입력 묶음 준비물·누구 것·버튼을 감싼 상자
<label> <input> 이름표와 입력칸 준비물 [____]
<select> <option> 골라 넣는 칸과 보기 누구 것 [가족 전체 ▼]
<button> 버튼 추가
<table> <tr> <td> 표, 표의 한 줄, 칸 하나 가족별 표 (누구 · 전체 · 챙김 · 챙김률 · 상태)
<ul> <li> <input type="checkbox"> 목록, 목록의 한 줄, 체크 상자 준비물 목록
<!-- --> 메모(화면에 안 보임) 코드 설명

💡 PRD에서 쓴 MD 파일과 비교해 보세요. MD의 # 이 HTML의 <h1>, - 항목 이 <li> 입니다. 구조를 표시한다는 생각은 같습니다.

2단계: CSS = 옷 (3분)

2-css.html 을 1단계와 번갈아 비교합니다. 같은 내용인데 제대로 된 앱 화면처럼 보입니다.

과정 뒤에 더 해 보기 코드 읽기 (과정 뒤)

HTML은 거의 그대로이고, 위쪽 <style> 안에 규칙이 추가됐습니다. 규칙 모양은 하나뿐입니다.

대상 { 속성: 값; }

button {
  background: #c8321e;   /* 버튼 배경을 소방 적색으로 */
  color: white;          /* 글자는 흰색 */
}
대상 쓰는 법 뜻 예
button 모든 버튼 추가 버튼
.bad class="bad" 가 붙은 것 "서둘러요" 글자 (빨강)
.ok class="ok" 가 붙은 것 "순조로움"·"다 챙김" 글자 (초록)
.num class="num" 이 붙은 것 전체·챙김·챙김률 숫자 칸 (오른쪽 정렬)
.wrap class="wrap" 이 붙은 것 가운데 기둥

3단계: JavaScript = 근육 (7분)

아래 화면은 3-js.html 입니다. 이번엔 표와 목록이 비어 있습니다. 준비물 멀미약·여벌 옷·체험학습 보고서 를 누구 것 아이 로 골라 차례로 [추가] → 목록과 가족별 표에 생깁니다. 그중 하나만 체크하면 아이 줄이 3개 중 1개, 33%, "서둘러요" 로 저절로 바뀝니다. 처음으로 화면이 계산을 했습니다.

수업에서는 위 실습의 ✏️ 코드 직접 고쳐 보기로 아래 표의 ③ rate < 50 한 줄을 직접 고쳐, 그 줄이 PRD 규칙이라는 것을 확인합니다. 나머지는 과정 뒤에 읽어 봅니다.

과정 뒤에 더 해 보기 코드 읽기 (과정 뒤)

맨 아래 <script> 안이 JavaScript입니다. 주석(//)을 따라 다섯 부분으로 읽습니다.

부분 하는 일 PRD와 연결
① 화면 요소 찾기 id로 입력칸·가족별 표·목록을 찾아 둠
② items 추가한 준비물을 모아 두는 상자 (새로고침하면 비워짐) "준비물 추가"
③ isHurry() 챙김률이 50보다 낮으면 서둘러요 "챙김률 50% 미만이면 서둘러요"
④ draw() 누구 것이 같은 준비물끼리 묶어 전체·챙김·챙김률 계산, 목록과 체크 상자 그리기 "가족별 집계" (v0.3)
⑤ 버튼·체크를 누르면 빈칸 검사 → 상자에 넣기 → 다시 그리기 (체크해도 다시 그리기) "입력 검사", "챙김 체크"

💡 ③번을 보세요. PRD에 한국어로 쓴 규칙 "챙김률 50% 미만이면 서둘러요"가 코드에서는 rate < 50 한 줄입니다. PRD를 코드로 옮기는 것, 그게 프로그래밍입니다.

④번의 const key = it.who; 가 모듈 5에서 고친 구멍입니다. 누구 것(who) 구분을 빼면 모든 준비물이 가족 전체 한 줄로만 세어집니다. 예시처럼 할머니 3개(다 챙김)·아이 3개(1개 챙김)·가족 공용 2개(다 챙김)를 넣으면 "8개 중 6개, 75%, 순조로움"이 되고, 아이의 "서둘러요"가 화면에서 사라집니다. Claude에게 "누구 것 구분(who)을 빼면 어떻게 되는지 미리보기로 보여 줘"라고 해 보면 PRD 한 줄의 무게가 실감 납니다.

4단계: 완성본 = 기억과 편의 (함께 보기, 4분)

아래 화면은 index.html (모듈 7에서 Claude가 만든 것과 같은 기능)입니다. 3단계에서 무엇이 더해졌는지 확인하고, 몇 개 체크한 뒤 [새로고침] 을 눌러 그대로 남는지 봅니다.

② JavaScript가 할 수 있는 일 10가지

세 재료 중 화면을 살아 움직이게 하는 것은 JavaScript입니다. 공통점은 새로고침 없이 그 자리에서 바로 바뀐다는 것입니다.

번호 예시 JavaScript가 하는 일 업무에서 쓰면
1 계산하기 입력값을 읽어 계산하고 결과를 표시 준비 체크리스트 진행률 계산
2 입력값 검사 입력 형식이 맞는지 실시간으로 판단 전화번호·날짜 형식 확인
3 실시간 시계 1초마다 화면을 다시 그림 시험 남은 시간 표시
4 다크 모드 버튼 하나로 모양을 통째로 바꿈 야간 상황실 화면
5 할 일 목록 화면 요소를 새로 만들고 지움 점검 체크리스트
6 글자 수 세기 입력 길이를 세고 기준을 넘으면 경고 공문 제목 글자 수
7 무작위 색 난수를 만들어 화면에 적용 발표 순서 뽑기
8 접고 펴는 안내문 누르면 내용을 보이거나 숨김 자주 묻는 질문
9 목록 검색 많은 자료에서 조건에 맞는 것만 거름 교육생 명단 찾기
10 퀴즈 채점 답을 판단하고 점수를 쌓음 복습 문제

파일 하나로 끝나는 화면 외부 라이브러리를 쓰는 화면
인터넷 없어도 열림 있어야 열림 (라이브러리를 받아 옴)
행정망 대부분 그대로 열림 라이브러리 주소가 막히면 빈 화면
이 과정의 프롬프트 "외부 라이브러리 없이"를 넣음 필요할 때만, 열리는지 확인하고 씀

라이브러리를 파일 안에 통째로 넣는 방법도 있습니다. 아래 3D 방 꾸미기 완성 예시가 그렇게 만들어져 있어서, 파일은 커지지만(약 600KB) 인터넷 없이 더블클릭만으로 열립니다.

그래서 이 과정의 프롬프트에는 "외부 라이브러리 없이, 파일 하나로" 를 넣습니다. 화면이 하얗게 나오면 F12 → Console에 빨간 오류가 있는지 보고, 외부 주소를 불러오지 못한 것이면 "외부 라이브러리 없이 다시 만들어 줘"라고 시킵니다.

준비물 화면은 작은 화면입니다. 같은 세 재료로 얼마나 큰 화면까지 되는지 직접 시켜 봅니다. 둘 중 하나를 고르세요. 두 화면의 완성 예시를 먼저 열어 보고 시작해도 됩니다.

A. 일정 플래너: 캘린더 + 간트차트 (Claude)

일정을 등록하면 월간 캘린더에, 프로젝트를 등록하면 간트차트에 보여 주는
일정 관리 화면을 HTML 파일 하나로 만들어 줘.
- 등록 창에서 "일정" / "프로젝트"를 고른다
- 일정: 제목, 날짜, 시작·종료 시간, 색, 메모 → 캘린더에 표시, 날짜를 누르면 그날 일정 목록
- 프로젝트: 제목, 시작일, 종료일, 진행률, 색 → 간트차트 막대, 끌어서 기간 이동·조절, 오늘 표시선
- 브라우저에 자동 저장, 삭제 후 되돌리기
- 부드러운 애니메이션, 깔끔한 디자인
- HTML·CSS·JavaScript만, 외부 라이브러리 없이

만든 뒤 찾아볼 것

화면에서 어느 재료가 한 일
캘린더 칸, 등록 창, 입력칸 HTML (무엇이 있나)
둥근 카드, 막대가 자라나는 움직임, 창이 커지며 열리는 효과 CSS (어떻게 보이나)
날짜 계산, 막대 끌기, 자동 저장, 삭제 되돌리기, 숫자 올라가는 효과 JavaScript (어떻게 움직이나)
  • F12 → Application → Local Storage 를 열면 저장된 일정이 글자로 보입니다. 완성본(4단계)과 같은 "이 브라우저에만" 저장입니다.
  • 업무에 쓰면: 교육 일정, 과정 운영 일정, 시설 점검 일정. 실제 개인정보·내부 일정은 넣지 않습니다.

B. 3D 방 꾸미기 (Claude)

3D로 방을 꾸미는 화면을 HTML 파일 하나로 만들어 줘.
- three.js 사용
- 바닥과 벽 두 면. 빈 곳을 끌면 방이 돌아가고, 휠로 확대·축소
- 가구 버튼(침대, 소파, 책상, 의자, 책장, 탁자, 화분, 스탠드, 러그)을 누르면 방에 놓이고, 끌어서 옮김 (벽 밖으로는 못 나감)
- 선택한 가구: 색 바꾸기, R 키로 돌리기, Delete 키로 지우기
- 벽 색, 바닥(마루·타일·단색), 낮·밤 바꾸기
- 브라우저에 저장, 사진(PNG)으로 저장

만든 뒤 확인할 것

  • Claude 미리보기나 내려받은 파일이 하얀 화면이면 F12 → Console 을 봅니다. three.js를 인터넷(cdn.jsdelivr.net, cdnjs, unpkg 등)에서 못 불러온 것이면 그 주소가 막힌 것입니다.
  • 코드에서 three 가 들어간 <script src="https://..."> 또는 import 줄을 찾아보세요. 이 한 줄이 남이 만든 3D 도구를 빌려 오는 줄입니다. 직접 쓰면 수만 줄인 3D 계산을 한 줄로 빌려 씁니다.
  • 완성 예시 파일은 같은 도구를 파일 안에 넣어 두어 인터넷 없이 열립니다. 같은 기능, 다른 선택입니다.
