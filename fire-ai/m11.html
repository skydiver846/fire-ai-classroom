선택 자료 11. Firebase로 "공용 장부" 연결하기 (수업 외)

📌 수업에서는 다루지 않는 선택 자료입니다. 10에서 배포한 화면의 응답을 한곳에 모으고 싶을 때 혼자 따라 해 보세요. 행정망에서는 Firebase 접속이 막힐 수 있습니다.

📌 강의장 인터넷 사정에 따라 직접 실습하거나 앞 화면 시연으로 진행합니다. 시연일 때는 화면을 보며 휴대폰으로 참여하고, 직접 해 보고 싶으면 수업 뒤에 이 페이지를 보며 따라 하면 됩니다.

1단계: Firebase 프로젝트 만들기 (5분)

  1. 업무 창에서 console.firebase.google.com (Google 서비스라 가입 없음)
  2. [프로젝트 만들기] → 이름 lecture-eval-12 → 약관 동의 → [계속]
  3. AI 도우미(Gemini) 질문이 나오면 원하는 대로 (사용 안 함도 가능)
  4. Google 애널리틱스: 사용 안 함 → [프로젝트 만들기] → 1분 대기 → [계속]
  5. ✅ 왼쪽 위에 lecture-eval-12, 가운데에 iOS·Android·</> 아이콘이 보이면 완료

2단계: 공용 장부(Firestore) 만들기 (5분)

  1. 왼쪽 메뉴 빌드(Build) → Firestore Database → [데이터베이스 만들기]
  2. 에디션 선택이 나오면 Standard
  3. 위치: asia-northeast3 (서울) → ⚠️ 나중에 바꿀 수 없습니다
  4. 프로덕션 모드로 시작 → [만들기]

3단계: 장부 사용 규칙 정하기 (10분)

Firestore 화면 위쪽 규칙(Rules) 탭 → 내용을 모두 지우고 아래를 붙여넣기 → [게시(Publish)]

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /evaluations/{evalId} {
      // 결과는 누구나 볼 수 있다 (익명 평가라 이름이 없다)
      allow read: if true;
      // 새 평가는 정해진 칸만, 정해진 모양으로 쓸 수 있다
      allow create: if request.resource.data.keys().hasOnly(['subject', 'instructor', 'score', 'date'])
        && request.resource.data.keys().hasAll(['subject', 'instructor', 'score', 'date'])
        && request.resource.data.subject is string
        && request.resource.data.subject.size() > 0
        && request.resource.data.subject.size() <= 30
        && request.resource.data.instructor is string
        && request.resource.data.instructor.size() > 0
        && request.resource.data.instructor.size() <= 20
        && request.resource.data.score is int
        && request.resource.data.score >= 1
        && request.resource.data.score <= 5
        && request.resource.data.date is string
        && request.resource.data.date.matches('^[0-9]{4}-[0-9]{2}-[0-9]{2}$');
      // 한번 낸 평가는 고치거나 지울 수 없다 (지우기는 담당자가 콘솔에서)
      allow update, delete: if false;
    }
  }
}

4단계: 화면과 장부를 잇는 설정값 받기 (5분)

  1. 왼쪽 위 프로젝트 개요 → 가운데 </> (웹) 아이콘
  2. 앱 닉네임 강의평가 → Firebase Hosting 체크하지 않기 (배포는 Vercel이 함) → [앱 등록]
  3. 화면에 나오는 코드 중 const firebaseConfig = { ... }; 부분만 복사 → 옵시디언 02_참고자료 에 Firebase 설정값 노트로 저장
  4. [콘솔로 이동]
const firebaseConfig = {

  projectId: "lecture-eval-12-a1b2c",

5단계: PRD 고치기 → Claude로 코드 고치기 (15분)

① PRD를 먼저 고칩니다 (기준 문서는 언제나 PRD). 옵시디언에서 PRD를 v0.4 로:

  • 6번 범위 밖에서 "여러 기기 간 데이터 공유"를 삭제 → 이제 범위 안
  • 4번 핵심 기능에 "모든 기기에서 같은 결과표를 실시간으로 본다" 추가
  • 마지막 응답 취소와 전체 초기화는 범위 밖으로 이동 (장부 규칙상 지울 수 없음, 관리자 기능은 다음 단계)

② Claude 새 채팅에 PRD v0.4 + 현재 index.html 두 파일을 첨부하고:

첨부한 index.html은 강의평가를 브라우저(localStorage)에 저장하는 집계 화면이야.
첨부한 PRD v0.4에 맞게, 평가를 Firebase Firestore에 저장하도록 고쳐 줘.

- 내 Firebase 설정값은 아래와 같아:
  (여기에 firebaseConfig 붙여넣기)
- HTML 파일 하나로 유지하고, Firebase는 공식 CDN(gstatic.com)의 모듈 방식으로 불러와 줘
- 컬렉션 이름은 evaluations, 필드는 subject, instructor, score(1~5 정수), date(YYYY-MM-DD)만 써 줘
- 문서 ID는 Firestore가 자동으로 만들게 해 줘 (addDoc)
- 모든 평가를 실시간으로 받아서 과목·교관별 집계는 화면에서 해 줘
- 마지막 응답 취소, 전체 초기화, 예시 데이터는 없애 줘
- 나머지 화면 디자인과 개선 필요 판정(평균 3.5 미만)은 그대로 둬

③ 내 컴퓨터에서 먼저 확인: Claude 결과를 메모장에 index.html(UTF-8)로 저장 → 더블클릭 → 평가 제출 → Firebase 콘솔 Firestore → 데이터 탭에 evaluations 아래 기록이 생기면 성공

6단계: GitHub에 커밋 → 자동 배포 (5분)

  1. GitHub lecture-eval → index.html → 연필(✏️)
  2. 기존 내용을 Ctrl + A 로 모두 선택 → 새 코드로 붙여넣기
  3. [Commit changes…] → 메시지 강의평가를 Firebase 공용 장부에 저장 → [Commit changes]
  4. Vercel Deployments 에서 Ready 확인 (주소는 그대로)

⭐ Claude Code로 (선택): 5~6단계를 Claude Code에 맡길 수 있습니다. 저장소를 연결하고 "PRD v0.4에 맞게 index.html을 Firestore에 저장하도록 고치고 커밋해 줘"(5단계 지시문 그대로)라고 지시하면, 복사·붙여넣기 없이 커밋까지 됩니다. 단, Firebase 설정값과 보안 규칙은 사람이 직접 확인합니다. 방법은 모듈 12 참고.

7단계: 짝꿍과 같은 결과표 확인 (5분)

  1. 짝꿍과 같은 강의평가 주소(한 사람의 Domains 주소 QR)를 각자 휴대폰으로 열기
  2. 한 사람이 평가 제출 → 다른 사람 화면에 새로고침 없이 응답 수와 평균이 바뀌는지 확인
  3. 같은 과목에 다른 교관 이름으로 내 보기 → 결과표에 줄이 따로 생기는지 확인
  4. 강사 PC에서 Firebase 콘솔 데이터 탭을 띄워 평가가 쌓이는 모습 보여 주기 (이름 칸이 없는 것도 확인)
