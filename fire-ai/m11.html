Firebase로 "공용 장부" 연결하기 (수업 외)

📌 수업에서는 다루지 않는 선택 자료입니다. 모듈 10 마무리에서 본 "장부는 공유되지 않는다"를 직접 풀어 보고 싶을 때, 과정 뒤에 혼자 따라 해 보세요. 행정망 PC에서는 Firebase 저장이 막힐 수 있으니 집 PC나 휴대폰 데이터(LTE) 로 확인합니다.

모듈 10에서 배포한 여행 준비물 화면은 화면은 가족 모두가 열 수 있지만, 체크한 기록은 각자 휴대폰(브라우저)에만 남았습니다. 여기서는 모두가 함께 쓰는 장부(데이터베이스)를 붙여, 배우자가 체크하면 내 휴대폰 화면에도 바로 체크되게 합니다.

 모듈 10:   [내 휴대폰 장부]   [배우자 휴대폰 장부]      ← 따로따로
 여기서:    [내 휴대폰]   ─┐
           [배우자 휴대폰] ┼──▶  Firebase (공용 장부)   ← 모두가 같은 체크 목록
           [아이 휴대폰]  ─┘
단계 하는 일 도구 이미 배운 것
1 Firebase 프로젝트 만들기 Firebase 업무 구글 계정 (01)
2 공용 장부(Firestore) 만들기 Firebase
3 장부 사용 규칙 정하기 Firebase PRD의 "범위 밖" (05)
4 화면과 장부를 잇는 설정값 받기 Firebase
5 PRD 고치기 → Claude로 화면 고치기 Claude 파일 + 지시 (03)
6 Netlify에 다시 올리기 Netlify 10의 "다시 올리기"
7 두 휴대폰으로 같은 목록 확인 휴대폰 10의 장부 실습

시작 전에 알아 둘 것

  • 무료 요금제(Spark) 로 합니다. 결제 정보 입력이나 Blaze 업그레이드 안내는 누르지 않습니다.
  • 연습용 준비물만 넣습니다. 실제 업무 자료를 해외 클라우드에 저장하려면 기관의 개인정보·클라우드 규정 검토가 필요합니다. 공공기관 정식 서비스는 클라우드 보안인증(CSAP) 을 받은 클라우드나 기관 내부 서버로 만드는 것이 일반적입니다.
  • 흐름(PRD → 화면 → 장부 규칙 → 배포)은 어떤 클라우드를 쓰든 같습니다.

✋ 실습 약 5분 · 직접 해 보는 부분

1단계: Firebase 프로젝트 만들기 (5분)

  1. 업무 Chrome 프로필에서 console.firebase.google.com (구글 서비스라 따로 가입하지 않음)
  2. [프로젝트 만들기] → 이름 trip-checklist → 약관 동의 → [계속]
  3. AI 도우미(Gemini) 질문이 나오면 원하는 대로 (사용 안 함도 가능)
  4. Google 애널리틱스: 사용 안 함 → [프로젝트 만들기] → 1분 기다리기 → [계속]
  5. ✅ 왼쪽 위에 trip-checklist, 가운데에 iOS·Android·</> 아이콘이 보이면 완료

💡 애널리틱스를 끄는 이유: 지금 필요 없는 기능은 끕니다. PRD의 "범위 밖"과 같은 원칙입니다.

✋ 실습 약 5분 · 직접 해 보는 부분

2단계: 공용 장부(Firestore) 만들기 (5분)

  1. 왼쪽 메뉴 빌드(Build) → Firestore Database → [데이터베이스 만들기]
  2. 에디션 선택이 나오면 Standard
  3. 위치: asia-northeast3 (서울) → ⚠️ 나중에 바꿀 수 없습니다
  4. 프로덕션 모드로 시작 → [만들기]

💡 프로덕션 모드는 처음에 아무도 장부를 못 쓰게 잠근 상태입니다. 다음 단계에서 정한 규칙대로만 열어 줍니다. 테스트 모드는 당장은 편하지만 30일 뒤 자동으로 잠기고, 그동안 누구나 장부를 지울 수 있습니다.

✋ 실습 약 10분 · 직접 해 보는 부분

3단계: 장부 사용 규칙 정하기 (10분)

Firestore 화면 위쪽 규칙(Rules) 탭 → 내용을 모두 지우고 아래를 붙여넣기 → [게시(Publish)]

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /items/{itemId} {
      // 목록은 주소를 아는 가족 누구나 본다
      allow read: if true;
      // 새 준비물은 정해진 세 칸만, 정해진 모양으로 쓴다
      allow create: if request.resource.data.keys().hasOnly(['name', 'who', 'done'])
        && request.resource.data.keys().hasAll(['name', 'who', 'done'])
        && request.resource.data.name is string
        && request.resource.data.name.size() > 0
        && request.resource.data.name.size() <= 40
        && request.resource.data.who in ['가족 전체', '나', '배우자', '아이', '할머니']
        && request.resource.data.done == false;
      // 고칠 수 있는 것은 "챙겼다" 체크 하나뿐
      allow update: if request.resource.data.diff(resource.data).affectedKeys().hasOnly(['done'])
        && request.resource.data.done is bool;
      // 준비물 지우기는 허용 (가족 목록이라)
      allow delete: if true;
    }
  }
}

규칙을 PRD 말로 읽으면 이렇습니다.

  • "목록은 가족 누구나 본다" → allow read
  • "준비물은 이름(40자 이내)·누구 것·챙김 세 칸만 쓴다. 누구 것은 가족 다섯 가지 중 하나, 처음엔 안 챙김" → allow create
  • "나중에 바꿀 수 있는 건 체크 하나뿐" → allow update

💡 체크는 화면(JavaScript)에서도 검사하지만, 화면 코드는 누구나 고칠 수 있습니다. 마지막 문지기는 장부 규칙입니다.

⚠️ 이 규칙은 연습용입니다. 로그인이 없어서 주소를 아는 사람은 누구나 목록을 보고 체크하고 지울 수 있습니다. 주소는 가족 단톡방에만 보내고, 실제 서비스라면 로그인(Authentication)과 사람별 규칙을 더합니다.

✋ 실습 약 5분 · 직접 해 보는 부분

4단계: 화면과 장부를 잇는 설정값 받기 (5분)

  1. 왼쪽 위 프로젝트 개요 → 가운데 </> (웹) 아이콘
  2. 앱 닉네임 준비물 → Firebase Hosting은 체크하지 않기 (배포는 Netlify가 함) → [앱 등록]
  3. 화면의 코드 중 const firebaseConfig = { ... }; 부분만 복사 → 메모장에 붙여 내 업무 폴더 02_참고자료 에 Firebase 설정값.txt 로 저장
  4. [콘솔로 이동]
const firebaseConfig = {
  apiKey: "AIza…",
  authDomain: "trip-checklist-a1b2c.firebaseapp.com",
  projectId: "trip-checklist-a1b2c",
  …
};

💡 apiKey 라는 이름 때문에 비밀번호 같지만, 웹 앱 설정값은 비밀이 아닙니다. 화면 코드에 그대로 들어가 누구나 볼 수 있습니다. 장부를 지키는 것은 3단계의 규칙입니다. 나중에 다시 찾을 때: ⚙ 프로젝트 설정 → 일반 → 내 앱 → SDK 설정 및 구성 → 구성(Config)

✋ 실습 약 15분 · 직접 해 보는 부분

5단계: PRD 고치기 → Claude로 화면 고치기 (15분)

① PRD를 먼저 고칩니다 (기준 문서는 언제나 PRD).

  • 6번 범위 밖에서 "여러 기기 간 데이터 공유"를 지우기 → 이제 범위 안
  • 4번 핵심 기능에 "가족 모두의 휴대폰에서 같은 체크 목록을 실시간으로 본다" 추가
  • 예시 데이터와 전체 초기화는 범위 밖으로 옮기기

② Claude 새 채팅에 고친 PRD + 모듈 10의 index.html 두 파일을 첨부하고:

첨부한 index.html은 여행 준비물 체크를 브라우저(localStorage)에 저장하는 화면이야.
첨부한 PRD에 맞게, 준비물을 Firebase Firestore에 저장하도록 고쳐 줘.

- 내 Firebase 설정값은 아래와 같아:
  (여기에 firebaseConfig 붙여넣기)
- HTML 파일 하나로 유지하고, Firebase는 공식 CDN(gstatic.com)의 모듈 방식으로 불러와 줘
- 컬렉션 이름은 items, 필드는 name(글자), who(가족 전체·나·배우자·아이·할머니 중 하나), done(참/거짓)만 써 줘
- 새 준비물은 done을 false로 만들고, 체크할 때는 done 하나만 바꿔 줘
- 문서 ID는 Firestore가 자동으로 만들게 해 줘 (addDoc)
- 목록을 실시간으로 받아서 누구별 챙김률 계산은 화면에서 해 줘
- 예시 데이터와 전체 초기화는 없애 줘
- 나머지 화면 디자인은 그대로 둬
- 내려받을 수 있는 index.html 파일로 줘

💡 이 지시문은 모듈 3의 맥락 + 조건을 그대로 쓴 것입니다. "필드는 이것만", "done 하나만 바꾸기"가 3단계 규칙과 정확히 맞아야 저장됩니다. 규칙과 코드가 어긋나면 [추가]를 눌러도 아무 일이 없습니다. "계산은 화면에서" 조건이 없으면 장부 쪽에서 묶고 정렬하려다 색인(index)을 만들라는 오류가 날 수 있습니다.

③ 내 컴퓨터에서 먼저 확인: 받은 index.html 을 여행준비 폴더에 덮어쓰기 → 더블클릭 → 준비물 하나 추가 → Firebase 콘솔 Firestore → 데이터 탭에 items 아래 기록이 생기면 성공

✋ 실습 약 3분 · 직접 해 보는 부분

6단계: Netlify에 다시 올리기 (3분)

모듈 10의 다시 올리기와 같습니다.

  1. app.netlify.com → 내 사이트 → Deploys
  2. 여행준비 폴더를 폴더째 아래쪽 끌어다 놓는 칸에 놓기
  3. 1~2분 뒤 같은 주소로 새 화면이 열립니다

✋ 실습 약 5분 · 직접 해 보는 부분

7단계: 두 휴대폰으로 같은 목록 확인 (5분)

  1. 가족(또는 동료)과 같은 주소를 각자 휴대폰으로 열기
  2. 한 사람이 준비물을 체크 → 다른 사람 화면이 새로고침 없이 바뀌는지 확인
  3. 다른 사람이 준비물을 하나 추가 → 내 화면에도 생기는지 확인
  4. Firebase 콘솔 데이터 탭에서 기록이 쌓이는 모습 보기
 모듈 10:  배우자가 체크 → 내 휴대폰 ✗
 여기서:   배우자가 체크 → 내 휴대폰 ✓  (공용 장부)

💡 Claude Code로 해도 됩니다. 모듈 12처럼 GitHub 저장소와 Netlify를 연결해 두었다면, 5~6단계를 "PRD에 맞게 index.html을 Firestore에 저장하도록 고쳐 줘"(5단계 지시문 그대로)로 맡기고 합치기만 누르면 됩니다. 단, Firebase 설정값과 규칙은 사람이 직접 확인합니다.

💼 업무에서는? 행사 준비물·당직 점검표처럼 여러 사람이 함께 체크하는 목록에 같은 방법을 씁니다. 다만 업무 자료는 기관 규정을 먼저 확인하고, 간단히 모으기만 할 때는 네이버 폼이 더 쉽습니다.
