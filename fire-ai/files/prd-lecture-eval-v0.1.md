# PRD: 과정별 강의평가 결과 집계 (프로토타입)

| 항목 | 내용 |
|---|---|
| 작성자 | 교육운영팀 홍길동 (예시) |
| 작성일 | 2026-10-01 |
| 버전 | v0.1 (프로토타입) |
| 상태 | 초안 |

---

## 1. 배경·문제

- 과정이 끝나면 교육생 강의평가를 **네이버 폼**으로 받는다. 응답은 잘 모이지만, 결과보고서에 넣을 **과목·교관별 평균표와 개선 필요 과목**은 담당자가 결과를 엑셀로 내려받아 다시 계산·정리한다.
- 신임소방관 과정은 과목이 18개, 응답이 40명분이라 엑셀에서 과목별로 나누고 평균을 내는 데 **반나절**이 걸린다. 수식 범위를 잘못 잡아 틀리는 경우도 있다.
- 기수마다 폼을 복사해 과목·교관 이름을 고치는 일도 반복된다.
- 일부 과목은 **교관 2~3명이 반별로 나눠** 강의한다.
- 결과보고서가 늦어져 **다음 기수 강의 개선**에 반영할 시간이 부족하다.

## 2. 목표

- 교육생이 평가를 입력하면 **과목별 응답 수와 평균이 바로** 계산된다.
- 평균이 낮은 과목은 **"개선 필요"로 자동 표시**되어 결과보고서에 그대로 옮길 수 있다.
- 이번 프로토타입의 목표: **입력 → 집계 → 개선 필요 표시 흐름을 보여 주고 의견을 받는 것** (정식 시스템 아님)

## 3. 사용자

| 사용자 | 상황 | 원하는 것 |
|---|---|---|
| 교육생 (약 40명) | 과정 마지막 날, 휴대폰으로 평가 | 빠르고 **익명으로** 평가하기 |
| 교육운영 담당자 | 결과보고서 작성 | 과목별 평균과 개선 필요 과목을 한눈에 보기 |

## 4. 핵심 기능

| 우선순위 | 기능 | 설명 |
|---|---|---|
| 필수 | 평가 입력 | 과목 이름과 만족도(1~5점)를 고르고 [평가 제출] |
| 필수 | 과목별 집계 | **과목별로** 응답 수와 평균(소수 첫째 자리)을 표로 보여 줌 |
| 필수 | 개선 필요 판정 | 평균 **3.5 미만**이면 "개선 필요", 그 이상은 "양호" |
| 필수 | 요약 숫자 | 전체 응답 수 / 평가 과목 수 / 개선 필요 과목 수 |
| 필수 | 점수 검사 | 1~5점이 아니거나 과목을 비우면 안내 문구를 보여 주고 막기 |
| 있으면 좋음 | 마지막 응답 취소 | 잘못 낸 마지막 응답 하나를 지우기 |
| 있으면 좋음 | 전체 초기화 | 다음 기수를 위해 전부 지우기 (실수 방지를 위해 두 번 눌러 확인) |

## 5. 화면·흐름

```
[화면 위] 과정명 · "평균 3.5 미만은 개선 필요로 표시" 안내
[요약]   응답 N | 평가 과목 N | 개선 필요 N
[입력]   과목 [__________]  만족도 [1~5 ▼] [평가 제출]
[결과표] 과목 | 응답 수 | 평균 | 양호/개선 필요   (평균이 낮은 과목부터)
```

1. 교육생이 과목 이름을 입력하고 만족도를 고른 뒤 [평가 제출]
2. 결과표에서 그 과목의 응답 수와 평균이 바로 바뀌고, 요약 숫자도 바뀜
3. 과목을 비우거나 만족도를 고르지 않으면 "과목과 만족도를 입력한 뒤 제출하세요." 안내
4. 처음 열었을 때는 **예시 응답**을 "(예시)" 표시와 함께 보여 줌

## 6. 범위 밖 (이번에 하지 않는 것)

- 로그인, 본인 확인 (익명 평가)
- **여러 기기 간 데이터 공유** — 기록은 각 브라우저에만 저장 (데이터베이스 연결은 2차)
- 자유 의견(서술형) 입력과 분석 — AI 요약 실습으로 따로 다룸
- 문항별(강의 내용·방법·교재) 세부 평가
- 그래프, 엑셀 내보내기

## 7. 성공 기준

- [ ] 휴대폰 화면(폭 약 400px)에서 가로 스크롤 없이 모두 보인다
- [ ] 과목과 만족도를 고르고 버튼 한 번으로 결과표에 반영된다
- [ ] 평균 3.5 미만 과목은 "개선 필요"로 표시된다
- [ ] 1~5점이 아니거나 과목이 비어 있으면 제출되지 않고 안내 문구가 나온다
- [ ] 새로고침해도 기록이 남아 있다 (같은 브라우저)
- [ ] 교육운영 담당자 3명에게 보여 주고 개선 의견을 받는다
