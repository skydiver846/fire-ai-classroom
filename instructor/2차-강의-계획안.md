### 4시간에 들어가게 한 장치

- **v0.1은 데이터를 가짜로 만들고, 저장·자료 받기 코드를 함수 한곳에 모아 두게 합니다.** v0.2에서는 그 함수만 바꾸므로 고칠 양이 작고 실패가 적습니다.
- **Claude가 만드는 동안(3~10분) 단계 5 준비를 미리** 하게 합니다(Firebase 프로젝트 만들기, 서비스 키 확인).
- **API 트랙 예비 경로**: 서비스 키 승인이 안 된 사람은 **강사 공용 주소**(이 강의 사이트의 `/api/fire`)를 씁니다. 키는 강사 쪽에만 있어 교육생에게 키를 나눠 주지 않습니다.
- **사전 학습은 계정 준비와 개념만**(약 1시간 15분). 다만 공공데이터 **활용신청은 반드시 미리**(키 반영에 1시간~하루). Firebase 설치와 API 연결은 3교시에 강사가 설명 · 시연한 뒤 교육생이 따라 합니다.
- **연동이 막힌 사람의 안전장치**: 키 · 서버 함수 없이 쓰는 **강사 공용 주소**(`/api/fire`)로 API를 연결하면 10분 안에 필수 요건을 채울 수 있습니다. 4교시 제출 마감 전에 순회하며 연동이 안 된 사람을 이쪽으로 안내합니다.
- 최소 목표: v0.1 배포 주소만 있어도 투표에 참여할 수 있습니다.

### 0-2. 강사 공용 주소 (API 트랙 예비 경로)

이 강의 사이트에 **`https://www.jg-sobang.com/api/fire?sido=서울`** 을 만들어 두었습니다(저장소 `api/fire.js`). 키 없는 교육생이 이 주소에서 소방청 화재정보서비스의 **시도단위 화재발생현황**(그날 시도별 화재 접수 · 진행 · 상황종료 건수)을 받아 씁니다. `sido=전체` 는 전국, `date=20261118` 로 날짜 지정, 날짜를 빼면 오늘(자료가 없으면 어제)입니다.

**강사가 할 일 (한 번)**
1. vercel.com → `fire-ai-classroom` 프로젝트 → **Settings → Environment Variables**
2. Key `DATA_GO_KR_KEY` / Value: 강사의 **소방청_화재정보서비스** 일반 인증키(서비스 정보 화면의 64자리 한 줄). 강사도 데이터포털에서 이 API를 먼저 활용신청해야 합니다 / Environments 모두 → [Save]
3. **Deployments** → 맨 위 배포 ⋯ → **[Redeploy]** (환경 변수는 다시 배포해야 반영)
4. 휴대폰으로 위 주소를 열어 `"items":[{"station":…` 이 보이는지 확인. `서비스 키가 설정되지 않았습니다`면 2~3번, `공공데이터포털 오류`면 키 승인 반영 전
5. 2차 접속 점검 페이지(`/fire-ai-2/check.html`)의 "강사 공용 화재 현황 주소" 줄이 **응답 확인**이면 끝

**동작**: 다른 주소(교육생의 `○○.vercel.app`)에서도 부를 수 있게 CORS를 열었고, `s-maxage=600` 으로 10분 동안 Vercel CDN에 캐시해 교육생 20명이 새로고침해도 하루 호출 한도를 아낍니다. 응답에는 키를 넣지 않습니다. 시도는 서울·경기·부산 등 17개 중 하나(`?sido=경기`).

**서버 함수 수**: Vercel 무료 요금제 한도가 12개라, 공모 기능의 조회(`board`)를 `act` 의 GET으로 합쳐 자리를 만들었습니다. 11. 10. 1차 수요조사 · 교육 신청 함수 6개를 정리해 지금 6개입니다(퀴즈 3, 공모 2, 화재 현황 1). 6자리가 남습니다. 정리한 함수의 응답 자료는 Upstash에 그대로 남아 있습니다.

이 파일은 교육생 API 트랙 (가)의 **정답 예시**이기도 합니다. 막힌 교육생에게 보여 줄 수 있습니다.

## 4. 설명 두 번: 흐름도·식당 지도(1교시) / 열쇠와 규칙 + 설치 시연(3교시)

> 화면 자료는 **[2차-흐름도.md](2차-흐름도.md)** 의 1장(흐름도)·2장(식당 지도)을 그대로 띄웁니다. 설명을 두 번으로 나눈 이유는 흐름도 문서 3장(검토)에 정리했습니다: **설명은 결정하기 직전에.** 트랙은 PRD에서 정하므로 개념은 1교시에, 열쇠·규칙은 3교시 준비 단계에서 다루므로 보안은 3교시에.

### 설명 ① 흐름도와 식당 지도 (1교시 시작, 10분)

**(1) 1차에서 남긴 질문 (1분)**: 1차에서 짝이 내 화면에 기록을 넣었는데 **내 휴대폰에는 보이지 않았습니다.** 1차 마무리의 사다리 ⑥ "저절로 돌아가게(백엔드, 공공데이터 API)"를 다음 단계로 남겼는데, 오늘 그 칸을 엽니다.

**(2) 오늘의 흐름도 (3분)**: 흐름도 문서 1장. 강조할 것 세 가지.
- ①~⑤는 **1차와 같은 길**입니다. 오늘은 이 길을 혼자 갑니다.
- ⑥에서 두 갈래로 나뉘었다가 ⑧ 검증 → ⑨ 결재에서 **다시 같은 길**로 합쳐집니다. 결재·배포 방법은 트랙과 상관없이 같습니다.
- 📢 표시 두 곳만 강사가 말합니다. 나머지는 실습지.

**(3) 식당 지도 (4분, 완성본 두 개를 휴대폰 두 대로 보여 주며)**: 흐름도 문서 2장.
- 식당 비유 소개 (사전 학습에서 읽고 왔지만, 뿌리 강의를 듣지 않은 분들이라 처음 듣는다고 생각하고 천천히): 홀 = 화면, 주문서 = API, 주방 = 백엔드, 장부 = DB, 개업 = 배포.
- 1차는 홀 + 손님 수첩(localStorage)뿐이었다 → 짝 휴대폰에 안 보인 이유.
- **DB 트랙** = 우리가 함께 쓰는 **우리 장부**. 시연: 휴대폰 두 대로 DB 완성본을 열고 한쪽에서 체크 → 다른 쪽이 바로 바뀜.
- **API 트랙** = 기관이 관리하는 **남의 장부를 읽기만**. 홀이 거래처에 직접 주문하지 않고 **우리 주방(서버 함수)** 을 거침. 시연: API 완성본의 값·기준 날짜·출처.
- 한 줄 정리: "두 트랙 모두 주문서(API)를 씁니다. 차이는 **누구의 장부냐**입니다."

**(4) 내 주제는 어느 트랙? (2분)**: 여러 사람이 같이 채우면 DB, 매일 바뀌는 공공 자료가 쓸모 있으면 API. 실습지 단계 0의 주제 예시 표.

> 💡 사전 학습 ②에서 다섯 곳만 읽고 왔으므로, 식당 비유는 처음 듣는다고 생각하고 천천히 합니다. 뿌리 강의 사이트(`/ai-literacy/`)는 과정 뒤 더 읽을거리로 안내합니다.

### 설명 ② 열쇠와 규칙 + 설치 · 연결 시연 (3교시 시작, 10분)
