## 0. 강의 전 꼭 확인할 것 (강사)

1차 자료에는 **"Claude Team 사용 기간은 11. 16.경까지"** 라고 적혀 있습니다. 2차 날짜가 그 뒤라면 Claude Code를 쓸 수 없으니, 둘 중 하나를 먼저 정합니다.

| 상황 | 진행 방법 |
|---|---|
| **Team 연장 (권장)** | 1차 모듈 12와 같은 방법: Claude Code → GitHub → Netlify 자동 배포 |
| **연장 안 됨 (예비안 B)** | 무료 Claude 대화에서 `index.html` 을 받아 → GitHub `my-tool` 저장소에 **[Add file] → [Upload files]** 로 올림 → 이미 연결된 Netlify가 저절로 다시 배포. 결재(PR)·미리보기 단계는 빠지고, "검토 4문항"은 Claude 대화에서 묻습니다. API 트랙의 서버 함수 파일도 같은 방법으로 올릴 수 있지만 시간이 더 걸리므로 B안에서는 **DB 트랙 중심**으로 권합니다 |

그 밖에 확인할 것:

- [ ] **공공데이터포털 API를 강의장 밖에서 한 번 호출해 보기.** Netlify 서버(해외)에서 `apis.data.go.kr` 을 부를 때 막히는 서비스가 있을 수 있습니다. 아래 4-2의 예제 함수를 내 저장소에 미리 배포해 응답이 오는지 확인하고, 되는 API 2~3개만 교육생에게 안내합니다.
- [ ] **강의장(행정망) PC에서 Firebase 저장이 되는지 확인** (`firestore.googleapis.com`). 막히면 DB 트랙 확인은 휴대폰 LTE로 한다고 미리 알립니다(1차 모듈 11과 같음).
- [ ] 투표용 구글 폼과 제출용 구글 시트 만들기 (6장).
- [ ] 교수부장님께 시상 시각(4교시 끝 약 15분 전), 총평 1~2분 부탁.
- [ ] 1차 산출물이 없는 분(결석, 저장소 삭제 등)을 위한 **처음부터 시작용 안내**: 1차 모듈 12의 ①(저장소 만들기·Claude Code 연결)을 2교시 전 쉬는 시간에 함께 합니다.

## 4. 짧은 설명 ①: 데이터베이스와 공공데이터 API (1교시, 15분)

### 4-0. 1차에서 남긴 질문으로 시작 (2분)

1차 ⑧-6에서 짝의 화면에 기록을 넣으면 **내 휴대폰에는 보이지 않았습니다**. 그리고 1차 마무리의 사다리 ⑥ "저절로 돌아가게(백엔드, 공공데이터 API)"를 "다음 단계"로 남겼습니다. 오늘 그 칸을 엽니다.

### 4-1. 기록을 어디에 두나: 세 가지 장부 (5분)

```
 ① 내 브라우저(localStorage)   [내 휴대폰 장부]  [짝 휴대폰 장부]        ← 1차. 따로따로
 ② 데이터베이스(공용 장부)     [내 휴대폰] ─┐
                               [짝 휴대폰] ─┼──▶ Firebase (공용 장부)   ← 모두가 같은 기록
                               [팀장 PC]  ─┘
 ③ 공공데이터 API(남의 장부)   [내 화면] ──▶ [내 서버 함수] ──▶ 공공데이터포털  ← 남이 관리하는 최신 자료를 읽기만
```

| | ① 내 브라우저 | ② 데이터베이스 | ③ 공공데이터 API |
|---|---|---|---|
| 업무로 치면 | 내 수첩 | 부서 공용 대장 | 다른 기관에 공문으로 받는 자료 |
| 누가 쓰나 | 나만 | 주소를 아는 우리 모두 | 기관이 올리고, 나는 읽기만 |
| 맞는 주제 | 개인 기록, 체크리스트 | 여러 사람이 함께 채우는 점검표·신청 현황 | 날씨·대기질·화재 통계처럼 매일 바뀌는 자료 |
| 지키는 것 | 없음 (내 휴대폰 안) | **장부 규칙** (누가 무엇을 쓸 수 있나) | **서비스 키** (비밀번호처럼 숨김) |
| 오늘 트랙 | A | B | C |

### 4-2. 꼭 기억할 두 가지 (5분)

**① 데이터베이스: 마지막 문지기는 장부 규칙** (1차 모듈 11의 3단계)

- 화면(JavaScript)에서 검사해도, 화면 코드는 누구나 고칠 수 있습니다. 장부 규칙이 PRD의 "누가 무엇을 할 수 있나"를 그대로 옮긴 것이어야 합니다.
- Firebase의 `apiKey` 는 이름과 달리 **비밀이 아닙니다**(화면에 들어가는 설정값). 지키는 것은 규칙입니다.
- 업무 자료를 해외 클라우드에 저장하려면 기관의 개인정보·클라우드 규정 검토가 필요합니다. 오늘은 **연습용 자료만** 넣습니다.

**② 공공데이터 API: 서비스 키는 진짜 비밀, 그래서 "심부름꾼(서버 함수)"을 둔다**

```
 ✗ 안 되는 방법:  내 화면(키가 코드에 보임) ──▶ 공공데이터포털
                  · 누구나 F12로 키를 보고 가져갈 수 있음
                  · 대부분 브라우저가 직접 부르는 것을 막음(CORS), http 주소는 https 화면에서 막힘

 ✓ 오늘 방법:     내 화면 ──▶ Netlify 서버 함수(심부름꾼) ──▶ 공공데이터포털
                              키는 Netlify 설정(환경 변수)에만 있음, GitHub에도 올리지 않음
```

- 1차 ③ 읽을거리 "깃허브에 올리지 않는 것 = 비밀번호, API 키, .env 파일"을 다시 보여 줍니다.
- 서비스 키를 Claude Code 채팅창에 붙여넣지 않습니다. 사람이 Netlify 화면에서 직접 넣습니다.

### 4-3. 내 주제는 어느 트랙? (3분)

| 질문 | 예 → |
|---|---|

| 주제 | 트랙 | 화면 |

#### 트랙 C: 공공데이터 API 붙이기

사전 조건: data.go.kr에서 활용신청이 **승인된** API (승인 직후에는 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` 가 날 수 있어 사전 과제로 냄). 사전 신청을 못 한 분은 강사가 시연용으로 쓰는 공통 API로 하거나, 1차 모듈 12 부록(파일 데이터 `data.csv`)으로 합니다.

권장 API 예 (강의 전에 강사가 Netlify에서 호출되는지 확인한 것만 안내):

| API (공공데이터포털 검색어) | 보여 줄 값 | 주제 예 |
|---|---|---|
| 한국환경공단_에어코리아_대기오염정보 | 시도별 실시간 PM10·PM2.5 | 야외 훈련 가능 여부 |
| 기상청_단기예보 조회서비스 | 기온·강수확률 (격자 좌표 필요) | 오늘 훈련장 날씨 |
| 소방청 관련 통계 API (검색어 "소방청") | 화재 건수 등 | 화재 현황판 |

① 서비스 키 넣기 (사람이 직접, 2분)

- data.go.kr → 마이페이지 → 활용신청 현황 → 해당 API → **일반 인증키(Decoding)** 복사
- app.netlify.com → 내 사이트 → **Site configuration → Environment variables → Add a variable**
- Key: `DATA_GO_KR_KEY`, Value: 복사한 키 → [Create variable]
- ⚠️ 키를 Claude Code 채팅, GitHub, 화면 코드 어디에도 붙여넣지 않습니다.

② 서버 함수와 화면 고치기 (Claude Code 같은 대화)

```

API: (API 이름)  /  요청 주소: (활용신청 상세 화면의 End Point와 상세기능 이름)
보여 줄 값: (예: 서울의 PM10, PM2.5, 측정 시각)

- 서비스 키는 Netlify 환경 변수 DATA_GO_KR_KEY에 이미 넣어 두었어. 키 값은 묻지 마.
- 브라우저가 공공데이터포털을 직접 부르지 말고, Netlify 서버 함수
  netlify/functions/data.mjs 가 대신 불러서 필요한 값만 JSON으로 돌려주게 해 줘.
- 서비스 키는 함수 안에서 process.env.DATA_GO_KR_KEY 로만 읽고, 응답이나 화면에 절대 넣지 마.
- 결과는 JSON(type=json 또는 returnType=json)으로 받고, 실패하면 화면에
  "자료를 불러오지 못했습니다(기준 시각)"처럼 알기 쉽게 보여 줘.
- 화면 아래에 출처(공공데이터포털, 제공기관, 측정·기준 시각)를 적어 줘.
- index.html 하나와 함수 파일 하나만 만들어 줘. 추가 라이브러리는 쓰지 마.
- PRD.md의 "데이터" 항목과 변경 기록(v0.2)도 고쳐 줘.
- 내 환경에는 키가 없어서 실제 호출 시험은 못 할 거야. 시험하지 못한 것은 못 했다고 표에 적어 줘.
```

③ 확인: 미리보기 주소 → 값이 나오는지, F12 → Network 에서 화면이 부르는 주소가 `/.netlify/functions/data` 이고 **응답에 키가 없는지** 확인 → 결재

## 7. 자주 막히는 곳 (2차 새 내용만, 나머지는 1차 12·11 표 그대로)

| 단계 | 상황 | 해결 |
|---|---|---|
| 0 | Claude Code를 쓸 수 없음 (Team 기간 끝) | 예비안 B (0장): 무료 Claude 대화 → `index.html` → GitHub [Upload files] → Netlify 자동 배포 |
| B | [추가]를 눌러도 아무 일 없음, F12에 `permission-denied` | 규칙과 코드의 필드가 다름. "firestore.rules와 index.html의 필드 이름·종류가 정확히 같은지 표로 비교하고 맞춰 줘" |
| B | 강의장 PC에서만 저장 안 됨 | 행정망이 `firestore.googleapis.com` 을 막은 것. 휴대폰 LTE로 확인 (1차 11과 같음) |
| C | `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` | 승인 직후 키 반영 전. 1시간~하루 기다림. 오늘은 강사 공통 API나 1차 부록(`data.csv`)으로 |
| C | `SERVICE KEY IS NOT REGISTERED` 가 계속 / 키 오류 | Encoding 키와 Decoding 키를 바꿔 넣어 봄 (예시 함수는 Decoding 키 기준) |
| C | 화면에 "서비스 키가 설정되지 않았습니다" | Netlify 환경 변수 이름이 `DATA_GO_KR_KEY` 와 정확히 같은지 확인 → 환경 변수를 넣은 **뒤에** 배포가 다시 되어야 함: Deploys → [Trigger deploy] → Deploy site |
| C | 결과가 XML로 옴 / JSON 읽기 오류 | API마다 `type=json` 또는 `returnType=json` 이름이 다름. 활용신청 상세 화면의 요청 변수 표를 Claude에게 붙여넣고 "이 명세에 맞게 고쳐 줘" |
| C | 함수 주소가 404 | 함수 파일이 `netlify/functions/` 폴더에 있는지 확인. 미리보기·운영 주소에서만 동작함 (PC에서 index.html 더블클릭으로는 안 됨) |
| C | Netlify에서 공공데이터포털 응답이 없음(시간 초과) | 해외 서버 호출을 막는 서비스일 수 있음. 강사가 미리 확인한 다른 API로 바꿈 |
| 투표 | 폼이 "로그인 필요" | 업무 구글 계정 Chrome 프로필에서 열기 |
