## 1. 5-API-1. 주소창에서 키 시험

### 결과 읽는 법
| 화면에 보이는 것 | 뜻 | 할 일 |
|---|---|---|
| `"resultCode":"00"`, `"NORMAL SERVICE"` | 키 인증 통과 | 정상 |
| `"totalCount":0`, `"items":[]` | 키는 되지만 그 날짜 자료가 없음 | 날짜 확인 |
| `SIDO_NM`, `FIRE_RCPT_MNB` 등이 보임 | 진짜 자료 수신 성공 | 다음 단계로 |
| `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` | 승인 반영 전 | 그대로 5-API-2 진행 |

### 확인된 주의점
- **예시 날짜(`20261118`)를 그대로 쓰면 빈 결과가 나온다.** 수강생이 주소 끝 날짜를 오늘 날짜로 바꾸지 않는 실수가 생기기 쉬움.
- 당일 자료가 아직 집계 전이면 비어 있을 수 있으니 **어제 날짜**로도 시도.
- 응답에 `"SIDO_NM":null`인 줄이 섞여 나올 수 있음(공공데이터 특성). 화면에 빈칸·null이 보이는 원인.
- 일부 시도가 목록에 없는 것은 그날 접수 건이 없어서이며 오류가 아님.
- 주소창 캡처에 키 앞부분이 보이므로 **캡처 이미지를 공유하지 않도록** 안내.

### 왜 어떤 API를 신청해도 키가 같은가
- 공공데이터포털은 인증키를 **API마다가 아니라 회원 계정마다 하나** 발급한다.
- 활용신청은 새 키를 만드는 것이 아니라, 기존 키에 "이 API도 사용 가능" 권한을 추가하는 절차.
- `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`는 키는 있으나 새 API 권한이 아직 반영되지 않았을 때 발생.
- 키 하나가 유출되면 승인된 모든 API가 노출되므로 Vercel 금고(환경 변수)에만 보관.
- 재발급하면 그 키를 쓰던 모든 곳(Vercel 포함)을 새 키로 바꿔야 함.

## 2. 5-API-2. Vercel 금고(환경 변수)에 키 넣기

### 찾아가는 길
- 프로젝트 확인: 안내문은 `team-tool` 프로젝트 기준. 왼쪽 위 프로젝트 이름 옆 ⌃⌄로 전환.
- **Environments(환경 목록)와 Environment Variables(환경 변수)는 다른 메뉴.** 키는 Environment Variables에 넣음.
- 메뉴가 안 보이면 왼쪽 위 **Find** 칸에 `Environment Variables` 입력.

### 입력 순서
1. 오른쪽 위 **검은색 [Add Environment Variable]** 버튼 클릭 (입력 칸이 바로 펼쳐져 있지 않음)
2. Type: **Secret** 그대로 둠
3. Key: `DATA_GO_KR_KEY` / Value: 64자리 일반 인증키 (앞뒤 공백 없이)
4. Note: 비워 둬도 됨
5. Environments: 기본값이 **Production 하나만** 선택돼 있음 → 드롭다운에서 Preview, Development 추가
6. [Save] → 목록에 `DATA_GO_KR_KEY` 한 줄 추가되면 완료

### 헷갈리기 쉬운 것
- 흰색 **Link Shared Variable** 버튼, **Shared** 탭, **Add new variable**, **Import .env**는 이번 실습에서 사용하지 않음.
- Secret은 **저장 후 값을 다시 볼 수 없음** → `공공데이터 메모.txt`를 지우지 말고 원본으로 보관.
- Secret 변수는 Vercel에서 **Development 환경 선택이 막힐 수 있음**. 이 경우 Production · Preview만 선택해도 배포 사이트에서는 정상 작동.
- 강의용 새 프로젝트는 변수 목록이 비어 있거나 짧음(기존 `manage`에는 Firebase 변수 6개가 있음).
- 기존 `manage`의 변수들은 모두 Production만 체크되어 있음 → "모두 체크"와 비교 설명하기 좋은 예시.

### `DATA_GO_KR_KEY`라는 이름에 대해
- Vercel이나 공공데이터포털이 정한 값이 아니라 **강의 자료에서 정한 이름**.
- 서버 함수가 `process.env.DATA_GO_KR_KEY`로 꺼내 쓰므로 **철자·대소문자가 정확히 같아야** 함. 다르면 키를 못 찾고 예시 자료만 보임.
- **앞에 `VITE_`를 붙이면 안 됨.** Vite에서 `VITE_`로 시작하는 변수는 화면(브라우저) 코드에 포함되어 누구나 볼 수 있음. Firebase 설정값은 공개돼도 되지만 공공데이터 키는 비밀이라 일부러 붙이지 않음.

## 3. Firebase 프로젝트 만들기: Google 애널리틱스를 끄는 이유
- 이번 실습에 필요 없는 기능(방문자 통계 수집).
- 켜면 애널리틱스 계정 선택·생성, 위치 선택, 약관 동의 단계가 추가되어 수강생이 막히기 쉬움.
- 공공기관 실습 앱에서 이용자 행동 데이터를 수집할 이유가 없어 개인정보 부담도 줄어듦.
- 필요하면 나중에 프로젝트 설정에서 켤 수 있음.

## 4. DB 트랙과 API 트랙: 어디에 무엇을 붙여 넣나

| | DB 트랙 (장부 규칙) | API 트랙 (우리 주방) |
|---|---|---|
| 회색 지시문 상자 | **Claude Code 채팅창**에 보냄 | **Claude Code 채팅창**에 보냄 |
| 보내기 전에 바꿀 것 | `[firebaseConfig 붙여넣기]` → 실제 firebaseConfig 값 | `보여 줄 값: [예: ...]` → 구체적으로(예: "전라남도의 화재 접수 · 진행 중 · 상황 종료 건수와 기준 날짜") |
| Claude Code가 만드는 것 | `firestore.rules`, 수정된 `index.html` | `api/data.js`(서버 함수), 수정된 `index.html` |
| Firebase 콘솔 작업 | 있음: 규칙 내용을 Firestore → **규칙** 탭에 모두 지우고 붙여넣기 → [게시] | **없음** (Firestore와 무관) |
| 완료 기준 | Claude가 다 고쳤다고 하고 **규칙까지 게시** | Claude가 다 고쳤다고 하면 완료 |

### DB 트랙 순서
1. 지시문의 `[firebaseConfig 붙여넣기]`를 실제 값으로 바꿔 Claude Code에 보냄
2. 완료 후 "firestore.rules 내용을 채팅에 그대로 보여 줘" 요청
3. Claude Code가 보여 준 **규칙 코드**(`rules_version = '2';`로 시작)만 복사해 Firestore 규칙 탭에 붙여 넣고 [게시]

### 주의
- **한국어 지시문을 Firestore 규칙 탭에 넣으면 문법 오류로 게시되지 않음.** 규칙 탭에는 Claude Code가 만든 코드만 들어감.
- Firestore 생성 시 "테스트 모드(개발 및 테스트)"는 일정 기간 누구나 읽고 쓸 수 있게 열어 두는 설정 → 반드시 규칙 게시 단계까지 마치도록 안내.

## 5. 7-3. 결재하기 (Merge)
1. GitHub 저장소 위쪽 메뉴 **Pull requests** 탭 클릭 (저장소 첫 화면에는 결재 버튼이 없음)
2. Claude Code가 만든 요청서(`claude/...` 가지 이름) 열기
3. 같은 화면에서 Vercel 미리보기 주소로 ○/✕ 확인(7-1)
4. 화면 아래 초록색 **[Merge pull request]** → **[Confirm merge]**
5. 1~2분 뒤 운영 주소(`○○.vercel.app`) 새로고침해 v0.2 확인

- 운영 주소는 저장소 오른쪽 **About**이나 Vercel 프로젝트 화면에서 확인. (예: 기존 저장소는 `manage-three-tan.vercel.app`)
- Pull requests 탭이 비어 있으면 Claude Code가 아직 요청서를 올리지 않은 것.
