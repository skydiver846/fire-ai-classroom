## 단계 1. PRD 쓰기 (30분)

> 🎯 **목표**: 새 저장소를 만들고, AI 인터뷰로 PRD 한 장을 완성한다.
> 📌 1차 복습: PRD는 "무엇을, 누구를 위해, 어디까지 만들지" 정한 설계 요청서. **범위 밖**이 없으면 AI도 사람도 일을 끝없이 키웁니다.
> ⏭ **끝나면**: ✅ 점검 1 (PRD 점검표 확인) → 2교시 단계 2

### 1-1. 새 저장소 만들기 (3분) · ④ GitHub 탭

1. 오른쪽 위 **[+]** → **[New repository]**
2. **Repository name**: `team-tool`
3. **Private** 선택
4. **Add a README file** ✅ 체크 (빈 저장소면 Claude Code가 작업을 시작하지 못합니다)
5. 맨 아래 **[Create repository]** → `team-tool` 저장소 화면에 README가 보이면 됩니다

### 1-2. Claude에게 이 저장소 출입 권한 주기 (2분) · ④ GitHub 탭

1. 주소창에 **github.com/settings/installations** 를 넣고 엽니다
2. 목록의 **Claude** 옆 **[Configure]**
3. 아래 **Repository access** 에서 **Select repositories** → `team-tool` 을 추가 → **[Save]**

> 💡 1차 때 "All repositories"로 했다면 이 단계는 이미 된 것입니다.

### 1-3. AI 인터뷰로 PRD 쓰기 (20분) · ② Claude 탭

1. claude.ai 에서 **새 대화**를 엽니다 (Claude Code가 아닌 일반 대화)
2. 아래를 복사해 `[만들고 싶은 것]` 과 트랙을 내 것으로 바꿔 보냅니다
3. 질문에 하나씩 답합니다. 모르면 **"추천해 줘"**
4. 다 답하면 Claude가 PRD 한 장을 정리해 줍니다

```
너는 경험 많은 기획자야. 나는 소방학교 교직원이고 "[만들고 싶은 것]"을 기획하려고 해.
PRD를 쓰기 위해 나를 인터뷰해 줘.
- 한 번에 질문 1~2개만 해.
- 배경·목표·사용자·핵심 기능·화면 흐름·데이터·범위 밖·성공 기준 순서로 물어봐.

```

## 들어가기 전에: 저장하는 곳 세 군데

> 🎯 **목표**: 내 화면의 기록이 **어디에** 저장되는지 알고, 왜 데이터베이스를 붙이는지 한 장으로 이해한다.

| 무료 용량 | 약 **5 MB** | 화면 파일은 넉넉 | **1 GiB** |
| 무료 한도 | 없음 | 전송량 한 달 약 100 GB, 서버 함수 **12개** | 하루 읽기 5만 · 쓰기 2만 건 |
| 사라지는 때 | 사이트 데이터 지우기, 시크릿 창, 다른 PC | 내가 지울 때 | 내가 지울 때 |

**v0.1 과 v0.2 의 차이가 바로 이것입니다.**
- **v0.1**(지금까지): 기록이 **브라우저**에만 있습니다. 그래서 짝 휴대폰에는 내가 넣은 기록이 안 보입니다.
- **v0.2**(지금부터): 기록을 **데이터베이스**에 둡니다. 누가 넣든 모두의 화면에 바로 보입니다.
- **Vercel은 기록을 저장하지 않습니다.** 화면 파일을 올려 두는 곳입니다.

> 💡 **지금 보는 이 교안도 똑같습니다.** 글과 그림은 Vercel 파일, 체크박스 표시는 내 브라우저(다른 PC에선 사라짐), [공모 · 투표](contest.html)는 데이터베이스(모두가 같은 결과를 봄)에 있습니다.

**서버 함수 = 주방 창구**
- 저장소의 `api` 폴더 안 파일 하나가 창구 하나입니다. 화면이 부르면 Vercel이 그때만 잠깐 실행합니다.
- 비밀(서비스 키)은 이 창구 안에만 두고 화면에는 내보내지 않습니다. API 트랙 (가)에서 만드는 `api/data.js` 가 이것입니다.
- 무료는 **창구 12개**까지. 창구 하나가 여러 일을 할 수 있어서(예: 공모 창구 하나가 등록 · 제출 · 투표를 모두 처리) 오늘 만드는 화면은 0~1개면 충분합니다.

> ⚠️ **사진은 저장하지 않습니다.** 휴대폰 사진 한 장(2~5 MB)이면 브라우저 용량이 바로 차고, Firestore 기록 하나는 1 MiB까지입니다. 사진은 **주소(링크)** 만 글자로 저장합니다.
> 💡 무료 한도를 넘어도 **요금은 나오지 않습니다.** 결제 수단을 넣지 않았으니 그날(또는 그달) 잠시 멈출 뿐입니다. "Blaze · 업그레이드" 단추는 누르지 않습니다.

**오류 번호 읽기** (F12 → Network 에서 빨간 줄을 눌러 보면 번호가 보입니다)

| 번호 | 식당으로 치면 | 오늘 흔한 원인 |
|---|---|---|
| 403 / `permission-denied` | 장부 규칙이 막음 | (DB) 규칙과 화면의 칸이 다름, 규칙 [게시] 안 함 |
| 404 | 그런 메뉴(주소) 없음 | (API) 함수 파일 위치, 또는 PC에서 index.html 을 더블클릭해 열었음 |
| 500 | 우리 주방 사고 | (API) 금고에 키가 없음(환경 변수 이름 · 재배포) |
| 502 | 거래처 응답이 이상함 | (API) 서비스 키 미등록, XML로 옴, 요청 변수 이름 |

| 막히면 | 해결 |
|---|---|
| (DB) [추가]를 눌러도 아무 일 없음 | F12 → Console 에 `permission-denied` 면 규칙과 코드의 칸이 다른 것 → "firestore.rules와 index.html의 칸 이름·종류가 같은지 표로 비교하고 맞춰 줘". 규칙을 고쳤으면 콘솔에 다시 붙여넣고 [게시] |
| (DB) "The query requires an index" | "정렬·계산은 화면에서 하게 고쳐 줘" |
| (API) "서비스 키가 설정되지 않았습니다" | 환경 변수 이름이 `DATA_GO_KR_KEY` 인지, Preview에도 체크했는지 확인 → Vercel **Deployments** → 맨 위 배포 ⋯ → **[Redeploy]** |
| (API) `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` | 승인 뒤 반영 전(승인 직후엔 1시간쯤 걸리기도 함)이거나 키를 잘못 붙여넣은 것(앞뒤 빈칸, 일부만 복사). 바로 안 되면 (나) 강사 공용 주소로 바꾸기 |
| (API) 결과가 XML로 옴 | "요청 변수 표대로 JSON 형식 요청 이름을 resultType=json 으로 고쳐 줘" |
| 미리보기가 Vercel 로그인을 요구 | PC Chrome(로그인됨)으로 보거나, 4-3대로 Vercel Authentication 끄기 |
| 미리보기 주소가 안 보임 | 결재 요청서 아래 확인 목록이 끝날 때까지 1~2분. Vercel **Deployments** 에도 "Preview"로 보임 |
| 잘못 결재했음 | Vercel **Deployments** → 이전 배포의 ⋯ → **[Promote to Production]** 으로 즉시 되돌리기 |
