## 오늘 만드는 것

오늘은 1차 교육생이 함께 **과정을 마무리하는 날**입니다. 1차에서 따라 해 본 흐름을 혼자 끝까지 해 보고, 각자 만든 도구를 나누고 시상하며 마칩니다.

1차에서는 화면을 만들었지만, 기록이 **내 휴대폰에만** 남았습니다. 오늘은 거기서 한 걸음 더 갑니다.

### 오늘의 흐름도

```그림
 📢 설명 ① 식당 지도 (1교시 시작)
   │
 ① PRD ─ 데이터 항목에서 트랙 고르기 (DB / API / 다듬기)                ← 1교시 · 단계 0~1
   │
 ② 계획·승인 ─▶ ③ 화면 v0.1 (가짜 자료) ─▶ ④ 검토·결재 ─▶ ⑤ 자동 배포·휴대폰   ← 2교시 · 단계 2~4 (1차와 같은 길)
   │
 📢 설명 ② 열쇠와 규칙 (3교시 시작)
   │
 ⑥ 준비(사람) ─┬─ DB : Firebase 장부 만들기                              ← 3교시 · 단계 5
               ├─ API: 서비스 키를 Vercel 금고(환경 변수)에
               └─ 다듬기: 짝에게 v0.1을 써 보게 하고 고칠 점 3가지 (가점 없음)
 ⑦ 연결(AI)  ─┬─ DB : 장부 규칙 → 내가 읽고 게시, 화면이 장부에 기록      ← 단계 6
               └─ API: 우리 주방(서버 함수)이 공공데이터포털에 주문
 ⑧ 미리보기 검증 ──✕──▶ ⑦로                                              ← 단계 7
   │ ○
 ⑨ 결재·자동 배포 (v0.2) ─▶ ⑩ 짝 검증·정리 (v0.3) ─▶ 🏆 투표·시상          ← 4교시 · 단계 8~9
```

### 식당 지도: 오늘 만드는 것은 어디인가

사전 학습에서 본 것처럼 웹 서비스를 식당 하나로 봅니다. 홀 = 화면, 주문서 = API, 주방 = 백엔드, 장부 = 데이터베이스, 개업 = 배포.

```그림
 1차     [홀: index.html] ── 손님이 각자 [수첩: localStorage] 에 적음 → 짝 휴대폰엔 안 보임

 DB 트랙  [홀] ══주문서══▶ [공용 장부: Firebase] + [장부 규칙: 누가 보고·쓰고·고치나]
                            우리가 함께 쓰는 "우리 장부"

 API 트랙 [홀] ══주문서══▶ [우리 주방: 서버 함수] ══주문서══▶ [거래처: 공공데이터포털]
                            [금고: 환경 변수] 에 거래처 출입증(서비스 키)
                            기관이 관리하는 "남의 장부"를 읽기만
```

> 💡 두 트랙 모두 화면이 주문서(API)를 보냅니다. 차이는 **누구의 장부냐**입니다.

v0.2에서 둘 중 하나를 붙이면 **가점(최대 +15)** 이 있습니다. 사전 학습 ④·⑤에서 1차 화면에 붙여 본 것을 새 주제에 한 번 더 하는 것입니다.

> 💡 공공데이터가 내 주제와 잘 이어지지 않아도 괜찮습니다. 화면 한쪽에 "오늘 우리 지역 미세먼지"처럼 띄워 두면 됩니다. **연동해 보는 것 자체에 의미**를 둡니다(가점도 같습니다).
붙이지 않고 **🛠 다듬기 트랙**(기록은 1차처럼 이 휴대폰에만, 대신 짝 의견으로 완성도 높이기)으로 가도 됩니다. 기본 100점은 세 트랙 모두 같습니다.

| | 🗂 DB 트랙: 함께 쓰는 장부 | 🌤 API 트랙: 살아 있는 자료 |
|---|---|---|
| 무엇 | 여러 사람이 같은 기록을 보고 채움 | 공공데이터포털의 최신 자료를 화면에 보여 줌 |
| 도구 | Firebase (구글 계정으로 바로) | 공공데이터포털 + Vercel 서버 함수 |
| 이런 주제에 | 장비 점검표, 질문 모음, 행사 신청 현황 | 야외 훈련 가능 여부(대기질·날씨), 화재 통계 현황 |
| 지키는 것 | **장부 규칙**: 누가 무엇을 쓸 수 있나 | **서비스 키**: 비밀번호처럼 숨김 |
| 식당으로 치면 | 우리 장부 | 거래처(남의 장부)에 우리 주방이 주문 |

> 🛠 **다듬기 트랙**: 데이터 연동 없이, 3교시에 짝에게 v0.1을 써 보게 하고 고칠 점 3가지를 반영합니다. 단계 5·6 대신 "다듬기 v0.2"를 합니다.

## 단계 1. PRD 쓰기 (30분)

> 🎯 **목표**: 새 저장소를 만들고, AI 인터뷰로 PRD 한 장을 완성한다.
> 📌 1차 복습: PRD는 "무엇을, 누구를 위해, 어디까지 만들지" 정한 설계 요청서. **범위 밖**이 없으면 AI도 사람도 일을 끝없이 키웁니다.
> ⏭ **끝나면**: ✅ 점검 1 (짝과 PRD 점검표 확인) → 2교시 단계 2

### 1-1. 새 저장소 만들기 (3분) · ④ GitHub 탭

1. 오른쪽 위 **[+]** → **[New repository]**
2. **Repository name**: `team-tool`
3. **Private** 선택
4. **Add a README file** ✅ 체크 (빈 저장소면 Claude Code가 작업을 시작하지 못합니다)
5. 맨 아래 **[Create repository]** → `team-tool` 저장소 화면에 README가 보이면 됩니다

1. 주소창에 **github.com/settings/installations** 를 넣고 엽니다

### 1-3. AI 인터뷰로 PRD 쓰기 (20분) · ② Claude 탭

1. claude.ai 에서 **새 대화**를 엽니다 (Claude Code가 아닌 일반 대화)
2. 아래를 복사해 `[만들고 싶은 것]` 과 트랙을 내 것으로 바꿔 보냅니다
3. 질문에 하나씩 답합니다. 모르면 **"추천해 줘"**
4. 다 답하면 Claude가 PRD 한 장을 정리해 줍니다

```
너는 경험 많은 기획자야. 나는 소방학교 교직원이고 "[만들고 싶은 것]"을 기획하려고 해.
PRD를 쓰기 위해 나를 인터뷰해 줘.
- 한 번에 질문 1~2개만 해.
- 배경·목표·사용자·핵심 기능·화면 흐름·데이터·범위 밖·성공 기준 순서로 물어봐.
- 데이터 방식은 [DB 트랙: 여러 사람이 함께 쓰는 공용 장부(Firebase)] / [API 트랙: 공공데이터포털 자료 읽어 오기] / [다듬기 트랙: 이 브라우저에만 저장] 중 내가 고른 것으로 해.
  DB라면 "어떤 칸(이름·종류)을 저장하고, 누가 무엇을 쓰고 고칠 수 있는지"를 물어봐.
  API라면 "어떤 API의 어떤 값을, 어떤 기준으로 보여 줄지"를 물어봐. 주제와 관련이 적으면 화면 한쪽에 작게 보여 줘도 돼.
- 크기는 화면 1장, 핵심 기능 3개로 줄여 줘.
- 범위 밖에는 "로그인, 실제 개인정보"를 꼭 넣어 줘.
- 성공 기준 3개는 휴대폰에서 직접 눌러 확인할 수 있는 문장으로 써 줘.
  그중 1개는 데이터에 관한 것으로 해 줘. (예: "내가 체크하면 짝 휴대폰에도 체크된다", "화면에 오늘 측정 시각이 보인다")
- 내가 다 답하면 Markdown 형식의 PRD 한 장으로 정리해 줘.
- 내가 말하지 않은 내용은 [확인 필요]로 표시해.
```

### 1-4. 점검하고 저장하기 (5분)

1. 아래 표로 PRD를 점검합니다. 하나라도 ❌면 Claude에게 "○○를 고쳐 줘"
2. PRD 전체를 복사해 메모장에 붙여 **`PRD.md`** 로 저장합니다 (단계 2에서 통째로 붙여넣음)
3. 짝과 서로 표를 확인합니다

| 점검 | 확인 |
|---|---|
| 핵심 기능이 3개인가? | □ |
| "데이터" 항목에 트랙이 있고, DB면 **저장할 칸과 누가 무엇을 고치나**, API면 **API 이름과 보여 줄 값**이 적혀 있나? | □ |
| 범위 밖에 "로그인, 실제 개인정보"가 있나? | □ |
| 성공 기준 3개가 휴대폰에서 눌러 볼 수 있는 문장이고, 그중 1개가 데이터에 관한 것인가? | □ |
| `[확인 필요]` 가 남아 있지 않나? | □ |

**✅ 다음으로**: `team-tool` 저장소가 있고, 점검표가 모두 □→✅ 인 PRD가 메모장에 저장돼 있다. **✅ 점검 1 (1교시 끝)**

| 막히면 | 해결 |
|---|---|
| 인터뷰가 끝나지 않음 | "지금까지 답한 것으로 PRD 정리해 줘" |
| 트랙을 못 고르겠음 | "내 주제에는 DB와 API 중 무엇이 더 쓸모 있을지 한 줄씩 비교해 줘" |
| installations 화면에 Claude가 없음 | 1차와 다른 GitHub 계정으로 로그인한 것. 오른쪽 위 프로필에서 계정 확인 |

## 단계 2. 계획 받기 (10분)

> ⏭ **끝나면**: 단계 3 (계획 승인 → 만들기)

### 2-1. Claude Code에서 저장소 고르기 · ③ Claude Code 탭

1. **claude.ai/code** 화면의 입력창 근처에서 저장소를 고르는 칸을 눌러 **`team-tool`** 을 고릅니다 (1차의 `my-tool` 이 아닌지 꼭 확인)
2. 새 대화(세션)가 `team-tool` 로 시작되면 됩니다

### 2-2. PRD 붙여 계획 요청하기

아래를 복사해 맨 아래 `[여기에 PRD 붙여넣기]` 자리에 메모장의 PRD를 통째로 붙여 보냅니다.

```
아래 PRD를 저장소에 PRD.md 로 저장하고 커밋해 줘. 그다음 바로 만들지 말고 계획만 알려 줘.

이번 v0.1의 약속:
- 화면은 index.html 하나로 만들어 줘. 휴대폰에서 잘 보이게.
- 데이터는 아직 진짜로 연결하지 않아.
  · DB 트랙이면: 기록을 이 브라우저(localStorage)에 저장하되, 저장·불러오기 코드를 함수 몇 개로 한곳에 모아 줘.
    다음 단계에서 그 부분만 공용 장부(Firestore)로 바꿀 거야.
  · 다듬기 트랙이면: 기록을 이 브라우저(localStorage)에만 저장해 줘.
  · API 트랙이면: 진짜 자료 대신 "예시 자료"를 넣고 화면에 "예시 자료"라고 표시해 줘.
    자료를 받아 오는 코드는 함수 하나로 모아 줘. 다음 단계에서 그 함수만 진짜 주소로 바꿀 거야.
- 외부 사이트에서 무언가를 불러오지 마.

계획에는 이것만 알려 줘:
1. 화면 그림 (글자로 대충)
2. 핵심 기능 3줄
3. 저장할 칸(또는 받아 올 값)의 이름과 종류 표
4. 나에게 확인할 질문

[여기에 PRD 붙여넣기]
```

> 💡 **왜 가짜 자료로, 함수 한곳에?** 홀(화면)이 주문서를 내는 창구를 한곳으로 모아 두면, 3교시에는 그 창구의 주문 받을 곳만 수첩 → 장부(또는 우리 주방)로 바꾸면 됩니다. 화면 전체를 다시 만들지 않아 고장이 적습니다.
