## ① 계정 준비 (30분)

> 🎯 **목표**: 당일 쓰는 다섯 곳에 모두 로그인되고, 공공데이터 **서비스 키**를 받아 둔다. 설치나 연결은 하지 않습니다(당일 3교시).

모두 **업무 Chrome 프로필**(1차 때 쓴 구글 업무 계정)에서 합니다.

### 1-1. 1차 계정 다시 확인 (5분)

| 순서 | 열 주소 | 이렇게 보이면 됨 | 안 되면 |
|---|---|---|---|
| 1 | **github.com** | 오른쪽 위에 내 프로필 사진, 저장소 목록에 1차 저장소(예: `my-tool`) | [Forgot password?] 로 비밀번호 재설정. 새 PC면 메일로 온 인증 코드 입력 |
| 2 | **vercel.com** → [Log in] → **[Continue with GitHub]** | 대시보드에 1차 프로젝트가 보임 | GitHub로 로그인했는지 확인 (이메일 로그인은 다른 계정이 됨) |
| 3 | 1차 내 화면 `○○.vercel.app` (휴대폰으로) | 1차 화면이 열림 | Vercel 대시보드 → 프로젝트 → Domains 에서 주소 확인 |
| 4 | **claude.ai/code** | 저장소 목록에 `my-tool` 이 보임 | 왼쪽 아래 계정이 Team 인지 확인 (Switch organization). "Claude Code isn't available"이면 강사에게 |

### 1-2. Firebase 들어가 보기 (3분)

1. **console.firebase.google.com** 을 엽니다. 구글 업무 계정이라 **따로 가입하지 않습니다.**
2. 처음이면 약관 동의 화면이 나옵니다 → 동의 → [계속]
3. "Firebase에 오신 것을 환영합니다" 또는 프로젝트 목록 화면이 보이면 됩니다. **프로젝트는 만들지 않습니다.** 당일 3교시에 함께 만듭니다.

### 1-3. 공공데이터포털 가입 (7분)

1. **www.data.go.kr** → 오른쪽 위 **[회원가입]**
2. 가입 방법을 고릅니다(일반 회원). 본인 인증은 휴대폰 문자로 합니다.
3. 아이디 · 비밀번호 · 이메일을 넣고 가입을 마칩니다. 비밀번호는 수첩에 적어 둡니다.
4. 로그인해서 오른쪽 위에 **[마이페이지]** 가 보이면 됩니다.

### 1-4. 소방청 화재정보서비스 활용신청 (10분)

1. 데이터포털 첫 화면 검색창에 **소방청 화재정보서비스** 를 넣고 검색
2. 검색 결과에서 **[오픈 API]** 탭 → **소방청_화재정보서비스** 를 누릅니다 (주소: `www.data.go.kr/data/15077644/openapi.do`)
3. 상세 화면 오른쪽(또는 아래)의 **[활용신청]**
4. 신청 화면에서
   - **활용목적**: 웹 사이트 개발(또는 기타) → 내용 칸에 `교육 실습: 화재 현황 화면 만들기`
   - **상세기능**: 모두 체크 (적어도 **시도단위 화재발생현황 목록조회**)
   - 라이선스 표시 **동의** → **[활용신청]**
5. **[마이페이지] → 데이터 활용 → Open API → 활용신청 현황** 에서 방금 신청한 줄이 **승인** 인지 봅니다 (개발계정은 대개 바로 승인)

### 1-5. 인증키와 End Point 메모하기 (5분)

활용신청 현황에서 **소방청_화재정보서비스** 이름을 눌러 상세 화면을 엽니다. **"서비스 정보"** 칸에 참고문서 · 데이터포맷 · End Point · 일반 인증키가 보입니다. 아래 **두 가지만** **메모장에 복사해 `공공데이터 메모.txt` 로 저장**합니다. 당일 3교시에 그대로 씁니다.

| 메모할 것 | 화면에서 찾을 곳 | 예 |
|---|---|---|
| **일반 인증키** | "서비스 정보"의 **일반 인증키** 줄 | 숫자와 영문 소문자가 섞인 **64자리** 한 줄 (`a1b2c3…` 처럼 긴 글자) |
| **End Point** | "서비스 정보"의 **End Point** 줄 | `https://apis.data.go.kr/1661000/FireInformationService` |

> 💡 **상세기능 이름 · 요청 변수는 메모하지 않아도 됩니다.** 당일 교안의 시험 주소와 Claude Code 지시문에 이미 다 들어 있습니다. 궁금하면 "서비스 정보"의 **참고문서**(활용가이드 .docx, 한글 프로그램으로도 열림)에서 볼 수 있습니다.

> ⚠️ **서비스 키는 비밀번호와 같습니다.** 메신저 · 메일 · Claude 채팅 · GitHub에 붙여넣지 않습니다. 메모장 파일은 내 PC에만 두고, 당일 **Vercel 설정 화면에만** 직접 넣습니다.
> 💡 **인증키가 한 줄**입니다. 그대로 복사해 씁니다(앞뒤 빈칸이 딸려 오지 않게). 다른 API에서 **Encoding / Decoding 두 줄**이 보이면 같은 키를 두 가지로 적은 것이니 **Decoding** 쪽을 씁니다.
> 💡 화면의 "참고 1"(API 환경에 따라 인증키 적용 방식이 다를 수 있음)은 두 줄짜리 키에 대한 안내입니다. 한 줄 키는 신경 쓰지 않아도 됩니다.

**✅ ①이 끝나면**: 다섯 곳에 로그인되고, `공공데이터 메모.txt` 에 일반 인증키와 End Point가 적혀 있습니다.

| 막히면 | 해결 |
|---|---|
| 데이터포털에서 휴대폰 인증이 안 됨 | 다른 인증 방법을 고르거나, 집 PC · 휴대폰으로 가입 |
| 활용신청 현황이 "승인 대기" | 대부분 자동 승인입니다. 몇 시간 기다려도 그대로면 강사에게 알려 주세요 |
| 상세 화면에 일반 인증키가 안 보임 | 마이페이지의 **인증키** 메뉴에 있는 경우도 있습니다 |

## ④ 데이터베이스와 공공데이터 API, 개념 한 장 (10분)

> 🎯 **목표**: 당일 3교시에 무엇을 왜 하는지 미리 안다. **설치 · 연결은 하지 않습니다.** 당일 강사가 설명 · 시연하고 함께 합니다.

### 두 가지 연동, 한눈에

| | 🗂 데이터베이스 (Firebase Firestore) | 🌤 공공데이터 API (공공데이터포털) |
|---|---|---|
| 식당으로 치면 | **우리 장부**: 우리가 함께 쓰고 고치는 대장 | **남의 장부**: 기관이 관리하는 자료를 읽기만 |
| 무엇이 달라지나 | 내가 넣은 기록이 **다른 사람 휴대폰에도 바로** 보임 | 화면에 **매일 바뀌는 실제 자료**(오늘 화재 접수 건수 등)가 보임 |
| 어울리는 주제 | 장비 점검표, 질문 모음, 강의실 사용 현황 | 오늘 우리 시도 화재 현황, 출동 대비 상황판. **주제와 관련 없어도** 한쪽에 띄우면 됨 |
| 손에 쥐는 것 | **설정값**(`apiKey` 등): 비밀이 아님. 화면 코드에 그대로 들어감 | **서비스 키**: 진짜 비밀. 화면 코드에 넣으면 안 됨 |
| 무엇이 지키나 | **장부 규칙**: "누가 무엇을 쓰고 고칠 수 있나"를 PRD 그대로 옮긴 것 | **금고(Vercel 환경 변수)** 에 키를 두고, **우리 주방(서버 함수)** 이 대신 부름 |
| 당일 사람이 직접 할 일 | 프로젝트 · 장부 만들기, 규칙 읽고 게시하기 | 키를 Vercel 금고에 넣기 |
| 당일 AI(Claude Code)가 할 일 | 규칙 초안 쓰기, 화면이 장부에 기록하게 고치기 | 서버 함수 만들기, 화면이 그 함수를 부르게 고치기 |

```그림
 🗂 DB    [홀: 내 화면] ══주문서══▶ [공용 장부: Firebase] + [장부 규칙]

 🌤 API   [홀: 내 화면] ══주문서══▶ [우리 주방: 서버 함수] ══주문서══▶ [거래처: 공공데이터포털]
                                     [금고: 환경 변수에 서비스 키]
```

### 당일 3교시에 하는 순서 (미리 보기)

1. **강사 설명 · 시연** (10분): 위 그림과 열쇠 · 규칙 이야기, Firebase 만들기와 API 연결을 화면으로 보여 줌
2. **사람이 직접 준비** (10분): DB는 Firebase 프로젝트 · 장부 만들기, API는 ①에서 받은 서비스 키를 Vercel 금고에 넣기
3. **AI에게 연결 맡기기** (15분): 교안의 지시문을 Claude Code에 보내기
4. **미리보기로 확인하고 결재** (15분): DB는 두 휴대폰에 같은 기록, API는 실제 값과 기준 날짜

> ✅ **필수 제출**: 당일 산출물에는 둘 중 **하나 이상**을 반드시 연동합니다. 둘 다 해도 됩니다. 시간이 모자라면 키 없이 쓰는 **강사 공용 주소**(`www.jg-sobang.com/api/fire`)로 API를 연결하는 가장 쉬운 길도 있습니다.

## ⑤ 당일 만들 주제 하나 정해 오기 (5분)

당일에는 1차와 **다른 새 주제**로, 새 저장소에서 처음부터 만듭니다. 제출할 것은 없고, 메모 한 줄이면 됩니다. "매번 엑셀로 손으로 세는 일", "여러 사람에게 물어 모으는 일"이 좋은 주제입니다.

| 주제 예 | 붙이기 좋은 것 |
|---|---|
| 교육 장비 점검표 (교관 여럿이 같은 목록에 체크) | 데이터베이스 |
| 교육생 질문 모음 (질문을 남기고, 답한 것은 "답변함") | 데이터베이스 |
| 강의실 사용 현황 (오늘 누가 어느 강의실) | 데이터베이스 |
| 오늘 화재 현황판 (우리 시도 화재 접수 · 진행 · 종료 건수) | 공공데이터 API |
| 시도별 화재 비교 (오늘 전국 시도 접수 건수 순위 막대) | 공공데이터 API |

> 💡 공공데이터가 주제와 이어지지 않으면 주제는 그대로 두고 화면 한쪽에 "오늘 우리 시도 화재 접수 건수"를 띄우면 됩니다.

## 미리 알아 두면 좋은 것: 제출과 심사 기준

당일 마지막에 서로 투표해 1등에게 교수부장님 부상을 드립니다.

**참가 자격 (필수 제출)**: 마감까지 제출 · 주소가 열림 · **데이터베이스 또는 공공데이터 API 연동이 하나 이상 동작** · `PRD.md`·`README.md` 있음 · 실제 개인정보 없음 · 서비스 키 노출 없음

| 기준 | 배점 | 한 줄 |
|---|---|---|
| 쓸모 | 20 | 내일 업무에 바로 쓰겠는가 |
| 완성도 | 25 | 성공 기준이 실제로 되고, 처음 쓰는 사람도 헷갈리지 않는가 |
| 데이터 연동 | 20 | 연동이 제대로 동작하는가 (공공데이터는 주제와 관련 없어도 같음) |
| 검증과 개선 | 20 | 짝 의견을 받아 고친 기록(PRD 변경 기록)이 있는가 |
| 안전과 문서 | 15 | 사용 설명서(README)가 있고, PRD 범위 밖에 로그인·개인정보가 있는가 |

**제출 · 투표 · 결과 공개는 모두 교안 안에서 합니다.** 당일 [공모 · 투표](contest.html) 페이지에서 참가 등록 → 산출물 주소 제출 → 모두의 작품을 함께 보고 1인 3표 투표 → 결과 공개 순서로 진행합니다.
