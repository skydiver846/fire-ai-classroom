## ② 공공데이터 활용신청 (11. 16.(월)까지, 10분)

1. data.go.kr 회원가입·로그인
2. 검색창에 **한국환경공단_에어코리아_대기오염정보** (또는 쓰고 싶은 API) → **오픈 API** 탭 → [활용신청]
3. 활용 목적: "교육 실습" → 상세기능 모두 체크 → 신청
4. 마이페이지 → 데이터 활용 → **Open API 활용신청 현황**에서 승인 확인
5. 승인된 API를 눌러 아래 세 가지를 메모장에 복사해 저장해 둡니다. 당일 그대로 씁니다.
   - **End Point** (요청 주소)
   - 쓸 **상세기능** 이름 (예: 시도별 실시간 측정정보 조회)
   - **요청 변수** 표

> ⚠️ **일반 인증키(서비스 키)** 는 비밀번호와 같습니다. 메신저·메일·채팅에 붙여넣지 않습니다. 당일 Vercel 설정 화면에만 직접 넣습니다.
> 승인이 늦어지면 ⑥은 강사 공용 주소(`https://www.jg-sobang.com/api/air?sido=서울`)로 대신 해 봅니다.

## ③ 웹 서비스의 뿌리, 꼭 필요한 부분만 (11. 17.(화)까지, 50분)

### 먼저 한 장 요약: 웹 서비스 = 식당

| 웹 서비스 | 식당 | 2차에서 만나는 곳 |
|---|---|---|
| **프론트엔드** | 홀, 메뉴판, 주문 태블릿 | 내가 만드는 화면 `index.html` |
| **API** | 홀과 주방 사이의 **주문서** | 화면이 자료를 달라고 보내는 요청 |
| **백엔드** | 주방 | ⑥의 "우리 주방"(Vercel 서버 함수) |
| **데이터베이스** | 장부 | ⑤의 "공용 장부"(Firebase) |

| **배포** | 가게 개업 | GitHub에 결재 → Vercel이 자동으로 공개 (1차에서 해 봄) |

1차에서 만든 화면은 **홀만 있고, 손님이 각자 수첩에 적는 가게**였습니다. 그래서 짝이 적은 기록이 내 휴대폰에는 보이지 않았습니다. ⑤에서 **장부**를, ⑥에서 **주방과 거래처**를 붙여 봅니다.

## ⑤ 실습 A. 데이터베이스(Firebase) 공용 장부 붙여 보기 (11. 17.(화)까지, 60분)

**목표**: 1차에 만든 내 화면(`my-tool`)의 기록을, 내 휴대폰과 다른 사람 휴대폰에서 **같이 보이게** 만들어 본다.

1. 1차 강의 **11번 페이지**(www.jg-sobang.com/fire-ai/m11.html, Firebase로 "공용 장부" 연결하기)를 엽니다.
2. **1~4단계**를 따라 합니다: 프로젝트 만들기 → Firestore(서울, 프로덕션 모드) → 규칙 → 설정값. Firebase 화면의 메뉴 이름이 1차 때와 바뀌었으니, 2차 교안 [3교시](s3.html) 단계 5의 DB 트랙 순서를 함께 보세요(장부: 데이터베이스 및 스토리지 → Firestore, 웹 앱: 프로젝트 개요 → [+ 앱 추가] → 웹).
   - 3단계 규칙은 페이지의 예시(여행 준비물용)를 그대로 쓰지 말고, 내 화면에 맞게 Claude Code에 초안을 받습니다: "내 PRD.md에 맞는 Firestore 보안 규칙을 써 주고, 각 줄을 PRD 말로 설명해 줘"
3. 5~6단계는 페이지 맨 아래 💡 **"Claude Code로 해도 됩니다"** 방법으로 합니다. claude.ai/code → `my-tool` → "PRD에 맞게 index.html을 Firestore에 저장하도록 고쳐 줘" + 설정값 → [Create PR] → 미리보기 확인 → [Merge].
4. 7단계: 두 휴대폰으로 같은 주소를 열고 한쪽에서 넣은 기록이 다른 쪽에 바로 생기는지 확인합니다.

> ⚠️ 연습용 자료만 넣습니다. 결제 정보·Blaze 업그레이드 안내는 누르지 않습니다. 강의장(행정망) PC에서도 Firebase 저장과 실시간 목록이 되는 것을 확인했습니다(11. 9.).

**다 했으면 확인**
- [ ] 내 휴대폰과 다른 휴대폰에서 같은 기록이 새로고침 없이 보인다
- [ ] 내 장부 규칙을 PRD 말로 한 줄씩 설명할 수 있다

## ⑥ 실습 B. 공공데이터 API 붙여 보기 (11. 17.(화)까지, 40분)

② 활용신청이 승인된 뒤에 합니다.

**목표**: 공공데이터포털에서 실제 자료를 받아 보고, 1차 내 화면에 붙여 본다.

1. data.go.kr → 마이페이지 → Open API 활용신청 현황 → 승인된 API를 엽니다.
2. 상세 화면에서 **상세기능 하나**(예: 시도별 실시간 측정정보 조회)의 요청 변수 표를 봅니다. 화면에 요청 변수를 넣어 바로 실행해 보는 기능(미리보기 또는 [확인])이 있으면 써 봅니다.
   - 없으면 Claude 일반 대화에 요청 변수 표를 붙여넣고 "이 API를 브라우저 주소창에서 JSON으로 불러 보는 주소를 만들어 줘. 서비스 키 자리는 SERVICE_KEY 라고 비워 둬"라고 합니다. 받은 주소의 `SERVICE_KEY` 자리에 **내 키를 직접** 넣어 주소창에서 엽니다. (이 주소는 어디에도 공유하지 않습니다)
3. 나온 글자 덩어리(JSON)에서 내 화면에 보여 줄 값 **3개**와 **측정·기준 시각**이 어느 칸에 있는지 찾습니다. (예: `pm10Value`, `pm25Value`, `dataTime`)
4. 1차 `my-tool` 저장소에서 실제로 붙여 봅니다. vercel.com → 내 프로젝트 → Settings → Environment Variables 에 `DATA_GO_KR_KEY` 로 키를 넣고(모든 환경 체크), claude.ai/code 에 "Vercel 서버 함수 api/data.js 가 공공데이터포털을 대신 부르고 키는 process.env.DATA_GO_KR_KEY 로만 읽게 해서, 이 값들을 화면에 보여 줘" + 요청 변수 표 → [Create PR] → 미리보기 확인.

> ⚠️ 서비스 키는 Vercel 설정 화면과 내 브라우저 주소창에만 넣습니다. Claude 채팅·GitHub·메신저에는 넣지 않습니다.

> 💡 **내 화면과 관련이 없어도 괜찮습니다.** 1차 화면(예: 운동 기록, 여행 준비물)과 대기질이 아무 관련이 없어도, 화면 한쪽에 "오늘 우리 지역 미세먼지"를 띄워 보면 됩니다. 이번 실습은 **"남의 장부를 우리 주방을 거쳐 받아 오는" 연동 자체를 해 보는 데 의미**를 둡니다. 당일 산출물도 마찬가지입니다.

**다 했으면 확인**
- [ ] 화면에 실제 값과 측정·기준 시각, 출처가 보인다
- [ ] PC Chrome F12 → Network 에서 화면이 부르는 주소가 `/api/data` 이고, 응답에 서비스 키가 없다
- [ ] 막혔던 곳과 푼 방법을 메모해 두었다
