# 2차 산출물 심사 기준

> 강사·교수부장님용 문서입니다. 교육생에게는 사전 학습 자료와 실습지 마지막에 요약본을 줍니다.
> 구성: **기본 100점**(세 트랙 공통) + **데이터 연동 가점 최대 +15**(사전 학습의 선택 연구를 산출물에 반영한 사람).

## 1. 선정 방법

| 단계 | 누가 | 무엇을 |
|---|---|---|
| ① 참가 자격 확인 | 강사 | 2장의 다섯 가지. 하나라도 ✕면 투표 대상에서 빠짐 (마감 전에 본인에게 알려 고칠 기회를 줌) |
| ② 동료 투표 | 교육생 전원 | 3장 기준을 보고 **1인 3표** (자기 작품 제외). 득표순으로 1~3위 |
| ③ 상위 3명 1분 시연 | 상위 3명 | 한 줄 소개 + 휴대폰 화면 |
| ④ 1등 확정·시상 | 교수부장 | 득표 1위를 1등으로. **득표가 같거나 1표 차이**면 기준표 점수(기본 + 가점, 강사 사전 채점)를 보고 교수부장님이 결정 |

> 💡 선택안: 동료 투표만으로는 "보기 좋은 화면"에 표가 몰릴 수 있습니다. 공정성을 더 원하면 **동료 투표 50% + 기준표 점수 50%** 로 합산할 수 있습니다(득표율과 기준표 점수를 각각 100점으로 환산해 반씩). 이때는 강사가 마감 직후 상위 5개를 기준표로 채점해 두고, 교수부장님이 시연을 보며 확인합니다. 어느 방법인지 1교시 여는 말에서 미리 알립니다.

## 2. 참가 자격 (통과 / 탈락)

| # | 자격 | 확인 방법 |
|---|---|---|
| 1 | 마감 시각(4교시 20분)까지 제출 시트에 주소를 냈다 | 시트 |
| 2 | 배포 주소가 휴대폰에서 열린다 | 휴대폰 |
| 3 | `PRD.md` 와 `README.md` 가 있다 | 배포 주소 뒤에 `/PRD.md`, `/README.md` 를 붙여 열기 ※ |
| 4 | 화면·PRD·README에 실제 이름·전화번호·주소·내부 자료가 없다 | 화면과 3번 파일 훑기 |
| 5 | 공공데이터 **서비스 키**가 화면 코드·응답에 보이지 않는다 (API 연동한 사람) | PC Chrome에서 주소 열기 → F12 → Network → 자료를 부르는 줄의 응답, Sources의 `index.html` 에서 키 모양(긴 영문·숫자) 찾기 |

※ 저장소가 비공개라 강사가 GitHub에서 볼 수 없습니다. Netlify는 저장소의 파일을 그대로 공개하므로 `주소/PRD.md` 로 열립니다. **강의 전 리허설에서 내 사이트로 한 번 확인해 두세요.** 열리지 않으면 제출 시 PRD 화면을 캡처해 시트에 붙이게 합니다.

## 3. 기본 100점 (세 트랙 공통)

| 기준 | 배점 | 상 | 중 | 하 | 확인 방법 |
|---|---|---|---|---|---|
| **① 쓸모** 문제·사용자 | 25 | 실제 업무의 불편이 분명하고, 누가 언제 쓸지 구체적. 내일 바로 쓸 수 있음 (25) | 쓸 곳은 있지만 대상·상황이 흐림 (15) | 왜 필요한지 알기 어려움 (6) | 한 줄 소개, `PRD.md` 배경·사용자 |
| **② 완성도** 성공 기준·쓰기 쉬움 | 30 | 성공 기준 3개가 모두 됨. 처음 쓰는 사람도 30초 안에 무엇을 하는 화면인지 앎. 휴대폰에서 잘 보임 (30) | 성공 기준 2개가 됨, 또는 한두 곳에서 헷갈림 (18) | 1개 이하, 또는 화면이 깨짐 (7) | 휴대폰으로 직접 써 보기 + `PRD.md` 성공 기준 |
| **③ 검증과 개선** | 25 | `PRD.md` 변경 기록에 v0.1 → v0.2 → v0.3이 있고, 짝 검증에서 나온 고칠 점이 반영됨 (25) | 변경 기록은 있으나 짝 의견 반영이 보이지 않음 (15) | 변경 기록 없음 (5) | `주소/PRD.md` 맨 아래 변경 기록 |
| **④ 안전과 문서** | 20 | `README.md` 에 무엇·쓰는 법 3단계·주소·데이터가 어디 있는지가 있음. PRD 범위 밖에 "로그인·실제 개인정보"가 있음 (20) | README가 있지만 쓰는 법이나 데이터 위치가 빠짐 (12) | README가 한두 줄뿐 (4) | `주소/README.md`, `PRD.md` 범위 밖 |

> 개인정보·서비스 키 노출은 점수가 아니라 **2장 참가 자격**에서 걸러집니다. ④는 "안전하게 쓰도록 문서로 남겼나"를 봅니다.

## 4. 가점: 데이터 연동 (최대 +15)

사전 학습의 **선택 연구**(Firebase, 공공데이터 API)를 산출물에 반영한 사람에게 줍니다. 연구만 해 오고 산출물에 붙이지 않았으면 가점은 없습니다.

| 가점 | 🗂 Firebase 공용 장부 | 🌤 공공데이터 API |
|---|---|---|
| **+10 동작** | 두 기기에서 같은 기록이 새로고침 없이 보인다 | 실제 값과 측정·기준 시각, 출처가 보인다 (예시 자료 아님) |
| **+5 제대로** (+10을 받은 경우만) | 장부 규칙이 PRD의 "누가 무엇을 쓰고 고치나"와 맞고, PRD "데이터" 항목과 README에 그 내용이 적혀 있다 | 자료를 못 받으면 알기 쉬운 안내가 나오고, PRD "데이터" 항목과 README에 API 이름·출처가 적혀 있다 |

- 둘 다 붙여도 **최대 +15**입니다. 하나를 제대로 하는 쪽을 권합니다.
- API를 강사 공용 주소로 붙인 경우도 같은 기준으로 줍니다(서비스 키 승인이 늦은 것은 본인 책임이 아니므로).
- 확인 방법: 둘러보기 때 DB 작품엔 직접 기록을 넣어 보고, 작품 주인 휴대폰에 보이는지 봅니다. API 작품은 값 하나를 공공데이터포털(또는 에어코리아·기상청 누리집)의 같은 값과 대조합니다.

### 왜 이렇게 나눴나

- **기본 100점은 세 트랙이 같습니다.** 2차의 목적은 1차 흐름을 혼자 끝까지 해내는 것이므로, 연동을 하지 않고 다듬기에 집중한 사람도 1등을 할 수 있어야 합니다.
- **가점은 +15로 묶었습니다.** 기본 점수 한 기준의 "상"과 "중" 차이(약 10점)보다 조금 큰 정도라, 연동이 승부를 가를 수는 있지만 화면이 망가진 작품을 뒤집지는 못합니다.
- **완성도(30)** 가 가장 큽니다. 연동에 시간을 다 쓰고 성공 기준이 안 되면 가점보다 잃는 점수가 더 큽니다. 1교시 여는 말에서 이 점을 분명히 말해 줍니다.

## 5. 투표자용 한 장 (둘러보기 10분 동안, 작품 하나에 30초)

화면에 띄우거나 실습지 마지막에 둡니다.

| 30초 안에 볼 것 | 기준 |
|---|---|
| 한 줄 소개를 읽고: "나도 쓰겠다"는 생각이 드나? | ① 쓸모 |
| 설명 없이 눌러 보기: 무엇을 하는 화면인지 바로 아나? 눌러서 되나? | ② 완성도 |
| DB 작품엔 기록을 하나 넣어 보기 / API 작품엔 값과 시각 보기 | 가점 |
| (여유 있으면) 주소 뒤에 `/PRD.md` 를 붙여 변경 기록 보기 | ③ 검증과 개선 |

## 6. 교수부장·강사 채점표

강사가 마감 직후 상위 득표 작품(선택안이면 상위 5개)을 채점해 교수부장님 판단 자료로 드립니다.

| 번호 | 이름 | 도구 이름 | 트랙 | 자격 ✓ | ① 쓸모 /25 | ② 완성도 /30 | ③ 검증·개선 /25 | ④ 안전·문서 /20 | 기본 /100 | 가점 /15 | 합계 | 득표 | 한 줄 평 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| | | | | | | | | | | | | | |
| | | | | | | | | | | | | | |
| | | | | | | | | | | | | | |

**칭찬 부문** (선택, 상품 없이 박수): 한 기준만 특히 높은 작품을 부릅니다.
- 쓸모 최고: "가장 업무에 바로 쓸 도구"
- 가점 +15: "가장 깔끔한 장부 규칙" 또는 "가장 살아 있는 자료"
- 검증과 개선 최고: "짝 의견을 가장 잘 반영"

## 7. 교수부장 총평 참고 (1~2분)

- 오늘 한 일을 업무 말로: "기획(PRD) → 시안(v0.1) → 시범 운영과 점검(짝 검증) → 개선(v0.2·v0.3) → 결재와 공개"
- 미리 연구해 와서 공용 장부·공공데이터까지 붙인 분들께 한마디
- 실제 업무에 쓰려면: 로그인과 사람별 권한, 기관 개인정보·클라우드 규정 검토가 다음 단계
