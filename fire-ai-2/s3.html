🗂 DB 트랙: Firebase 설치

5-DB-1. Firebase 프로젝트 만들기 (3분)

  1. console.firebase.google.com → [프로젝트 만들기] (또는 [Firebase 프로젝트 시작하기])
  2. 프로젝트 이름: team-tool- + 내 이니셜 (예: team-tool-hgd) → [계속]
  3. Gemini(AI 도우미) 질문이 나오면 원하는 대로 → [계속]
  4. "이 프로젝트에서 Google 애널리틱스 사용 설정" 스위치를 끕니다 → [프로젝트 만들기]
    • "Google 애널리틱스 구성"(계정 선택) 화면이 나오면 [이전] 으로 돌아가 스위치를 끕니다
  5. 1분쯤 뒤 [계속] → "○○님, 안녕하세요" 첫 화면이 보이면 됩니다

5-DB-2. 장부(Firestore) 만들기 (3분)

  1. 왼쪽 제품 카테고리 → 데이터베이스 및 스토리지 → Firestore → [데이터베이스 만들기]
  2. 네 단계를 차례로 고릅니다
    • ① 버전 선택: Standard → [다음]
    • ② 데이터베이스 ID 및 위치: ID는 (default) 그대로, 위치 asia-northeast3 (Seoul) → [다음]. ⚠️ 위치는 나중에 못 바꿉니다
    • ③ 구성: 프로덕션 모드에서 시작 → [만들기]
    • ④ 예약된 백업: 하지 않음
  3. 위쪽에 데이터 · 규칙 · 색인 탭이 보이면 됩니다

💡 프로덕션 모드 = 처음에는 아무도 장부를 못 쓰게 잠근 상태입니다. 단계 6에서 PRD대로 만든 규칙을 게시해 필요한 만큼만 엽니다.

5-DB-3. 웹 앱 설정값 받기 (2분)

  1. 왼쪽 위 프로젝트 개요(집 모양) → 위쪽 [+ 앱 추가] → 웹(</>)
  2. 앱 닉네임 team-tool → Firebase 호스팅은 체크하지 않음 → [앱 등록]
  3. 나온 코드 중 const firebaseConfig = { 부터 }; 까지 복사 → 메모장에 붙여 둡니다 → [콘솔로 이동]

💡 apiKey 라는 이름이지만 비밀이 아닙니다. 화면 코드에 그대로 들어가는 설정값입니다. 장부를 지키는 것은 규칙입니다.

(나) 강사 공용 주소로 (키 승인이 아직 안 됐거나, 가장 빨리 연동하고 싶을 때)

🌤 API 트랙 (가) 우리 주방(서버 함수)

이제 v0.2로, 예시 자료 대신 공공데이터포털의 진짜 자료를 보여 주게 바꿔 줘.
API: 한국환경공단_에어코리아_대기오염정보 / 시도별 실시간 측정정보 조회 (다른 API면 이름과 요청 변수 표를 붙여넣기)
요청 주소: https://apis.data.go.kr/B552584/ArpltnInforInqireSvc/getCtprvnRltmMesureDnsty
요청 변수: serviceKey, returnType=json, sidoName=[우리 시도], numOfRows=100, ver=1.0
보여 줄 값: [예: 측정소 이름, PM10, PM2.5, 측정 시각]

- 서비스 키는 Vercel 환경 변수 DATA_GO_KR_KEY 에 이미 넣어 두었어. 키 값은 묻지 마.
- 브라우저가 공공데이터포털을 직접 부르지 말고, Vercel 서버 함수 api/data.js 가 대신 불러서
  필요한 값만 JSON으로 돌려주게 해 줘. 함수는 module.exports = async (req, res) => { … } 모양(Node.js)으로,
  package.json 없이 동작하게 해 줘. 키는 함수 안에서 process.env.DATA_GO_KR_KEY 로만 읽고 응답에 넣지 마.
- 함수 응답에 Cache-Control: s-maxage=600 을 붙여 10분 동안 캐시해서 호출 횟수를 아껴 줘.
- index.html에서는 v0.1 때 모아 둔 자료 받기 함수만 /api/data 를 부르게 바꾸고, "예시 자료" 표시는 지워 줘.
- 실패하면 화면에 "자료를 불러오지 못했습니다"처럼 알기 쉽게 보여 줘.
- 화면 아래에 출처(공공데이터포털, 제공기관, 기준 시각)를 적어 줘.
- 추가 라이브러리는 쓰지 마. PRD.md 변경 기록에 v0.2를 적어 줘.
- 네 환경에는 키가 없어서 실제 호출 시험은 못 할 거야. 시험하지 못한 것은 못 했다고 알려 줘.

번호 식당으로 치면 오늘 흔한 원인

막히면 해결
(DB) [추가]를 눌러도 아무 일 없음 F12 → Console 에 permission-denied 면 규칙과 코드의 칸이 다른 것 → "firestore.rules와 index.html의 칸 이름·종류가 같은지 표로 비교하고 맞춰 줘". 규칙을 고쳤으면 콘솔에 다시 붙여넣고 [게시]
(DB) "The query requires an index" "정렬·계산은 화면에서 하게 고쳐 줘"
(API) "서비스 키가 설정되지 않았습니다" 환경 변수 이름이 DATA_GO_KR_KEY 인지, Preview에도 체크했는지 확인 → Vercel Deployments → 맨 위 배포 ⋯ → [Redeploy]
