식당 지도: 오늘 만드는 것은 어디인가

사전 학습에서 본 것처럼 웹 서비스를 식당 하나로 봅니다. 홀 = 화면, 주문서 = API, 주방 = 백엔드, 장부 = 데이터베이스, 개업 = 배포.

 1차     [홀: index.html] ── 손님이 각자 [수첩: localStorage] 에 적음 → 짝 휴대폰엔 안 보임

 DB 트랙  [홀] ══주문서══▶ [공용 장부: Firebase] + [장부 규칙: 누가 보고·쓰고·고치나]
                            우리가 함께 쓰는 "우리 장부"

 API 트랙 [홀] ══주문서══▶ [우리 주방: 서버 함수] ══주문서══▶ [거래처: 공공데이터포털]
                            [금고: 환경 변수] 에 거래처 출입증(서비스 키)
                            기관이 관리하는 "남의 장부"를 읽기만

💡 두 트랙 모두 화면이 주문서(API)를 보냅니다. 차이는 누구의 장부냐입니다.

✅ 필수 제출: 오늘 산출물에는 데이터베이스(DB 트랙) 또는 공공데이터 API(API 트랙) 중 하나 이상을 반드시 연동해 제출합니다. 둘 다 붙여도 됩니다. Firebase 설치와 API 연결은 3교시 시작에 앞 화면으로 설명 · 시연을 함께 본 뒤 단계 5~7을 따라 합니다.

💡 공공데이터가 내 주제와 잘 이어지지 않아도 괜찮습니다. 화면 한쪽에 "오늘 우리 시도 화재 접수 건수"처럼 띄워 두면 됩니다. 연동해 보는 것 자체에 의미를 둡니다.

🆘 연동이 막혀 시간이 모자라면, 가장 쉬운 길은 API 트랙 (나) 강사 공용 주소입니다. 키 · 서버 함수 없이 10분이면 연결됩니다(단계 5 · 6).
