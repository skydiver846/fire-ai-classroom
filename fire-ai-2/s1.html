✋ 실습 약 30분 · 혼자 해 보는 부분

단계 1. PRD 쓰기 (30분)

1차 복습: PRD는 "무엇을, 누구를 위해, 어디까지 만들지" 정한 설계 요청서. 범위 밖이 없으면 AI도 사람도 일을 끝없이 키웁니다.

1-1. 저장소 만들기 (5분)

  1. github.com → 오른쪽 위 [+] → [New repository]
  2. 이름 team-tool, Private, Add a README file ✅ → [Create repository]
  3. Claude에게 이 저장소 출입 권한 주기: github.com/settings/installations → Claude 옆 [Configure] → Repository access 에 team-tool 추가 → [Save]

1-2. 인터뷰 (20분): Claude 일반 대화(claude.ai)에 아래를 붙여넣고 질문에 답합니다. 모르면 "추천해 줘".

너는 경험 많은 기획자야. 나는 소방학교 교직원이고 "[만들고 싶은 것]"을 기획하려고 해.
PRD를 쓰기 위해 나를 인터뷰해 줘.
- 한 번에 질문 1~2개만 해.
- 배경·목표·사용자·핵심 기능·화면 흐름·데이터·범위 밖·성공 기준 순서로 물어봐.
- 데이터 방식은 [DB 트랙: 여러 사람이 함께 쓰는 공용 장부(Firebase)] / [API 트랙: 공공데이터포털 자료 읽어 오기] / [다듬기 트랙: 이 브라우저에만 저장] 중 내가 고른 것으로 해.
  DB라면 "어떤 칸(이름·종류)을 저장하고, 누가 무엇을 쓰고 고칠 수 있는지"를 물어봐.
  API라면 "어떤 API의 어떤 값을, 어떤 기준으로 보여 줄지"를 물어봐.
- 크기는 화면 1장, 핵심 기능 3개로 줄여 줘.
- 범위 밖에는 "로그인, 실제 개인정보"를 꼭 넣어 줘.
- 성공 기준 3개는 휴대폰에서 직접 눌러 확인할 수 있는 문장으로 써 줘.
  그중 1개는 데이터에 관한 것으로 해 줘. (예: "내가 체크하면 짝 휴대폰에도 체크된다", "화면에 오늘 측정 시각이 보인다")
- 내가 다 답하면 Markdown 형식의 PRD 한 장으로 정리해 줘.
- 내가 말하지 않은 내용은 [확인 필요]로 표시해.

1-3. 점검 (5분): 하나라도 ❌면 Claude에게 "○○를 고쳐 줘". 끝나면 짝과 서로 확인합니다.

점검 확인
핵심 기능이 3개인가? □
"데이터" 항목에 트랙이 있고, DB면 저장할 칸과 누가 무엇을 고치나, API면 API 이름과 보여 줄 값이 적혀 있나? □
범위 밖에 "로그인, 실제 개인정보"가 있나? □
성공 기준 3개가 휴대폰에서 눌러 볼 수 있는 문장이고, 그중 1개가 데이터에 관한 것인가? □
[확인 필요] 가 남아 있지 않나? □
